+   gdb Commands 
    url: https://www.tutorialspoint.com/gnu_debugger/gdb_commands.htm
    b           breakpoint at current line 
    b main      puts a breakpoint at the beginning of the program 
    b <N>       puts a breakpoint at line N
    b +<N>      puts a breakpoint N lines down from the current line
    bt          prints a stack trace
    c           Continues running the program until the next breakpoint or error
    d           Goes down a level in the stack
    d <N>       delete breakpoint <N>
    f           runs until the current function is finished
    info break  list breakpoints
    l           list current 5? code lines 
    n           like s, but it does not step into functions  - STEP.over
    p <v>       prints the current value of the variable "v"
    q           Quits gdb
    r           runs the program until a breakpoint or error
    s           "step" runs the next line of the program - STEP.into
    s <N>       Runs the next N lines of the program
    u           goes up a level in the stack
    u <N>       runs until you get N lines in before the current line
    <ENTER>     like STEP s

+   gdb Workflow
    a) run (r) Start program execution from beginning. It should stop at main()
    b) next (n) Execute next line of code. Will not enter function.
    c) step (s) Step to next line of code. Will step into function.
    d) continue (c) Continue executing until next breakpoint. Should stop at Place_Order()
    e) Continue stepping until the segfault occurs
    f) quit (q) Exit GDB debugger

        int foo() {
            #ifdef __USE_SPEC 
                return 5;
            #else   
                return 1;
            #endif

        TC.001 : expected: return 1;

            so würde result(TC.001)=:error  sein.
        Soll ein Test je Compiler verschieden sein,
            muss TC.001 als 
        allgemeiner TC entfernt werden.
        Dasgeht mit dem Attribut "Specialized".

+   TestCase Data 
        a) "SBF" vs b) "Stubbed Subprograms"
    Im TestCase steht oben SBF und weiter unten 
        Stubbed Subprograms.
    
    zu a)  
    Es bedeutet :   "SBF"
            Stub By Function
    Hier stehen die implementierte Funktionen, welche 
        in der Unit stehen (der Source, 
            C-File oder includiertes H-File ).
    VectorCAST ruft normalerweise alle Funktionen in einer 
        Unit auf.
    Ist das nicht erwünscht, und soll nur der return-Wert
        betrachtet werden,
        so muss die SBF-Funktion markiert und der return-Wert 
        bestimmt werden.

    zu b)
        Hier stehen, die Funktionen, die ausserhabl des Codes (Unit)
        implementiert werden, oder nur als Stub zur Verfügung stehen. 
        Parameter und Return-Werte können <nur> auf der Input-Seite 
            angegeben werden.
