>>>	K1.06:	Cloud Grundsätze (Prinzipien)


+   Cloud Computing 
    is the delivery of computing 
            services—including servers, 
            storage, 
            databases, networking, software, 
                and analytics—over the internet ("the cloud"). 
    Instead of buying and maintaining physical data centers, 
        businesses rent access to infrastructure and 
        applications on a pay-as-you-go basis from providers 
    like AWS, Microsoft Azure, and Google Cloud.


+   Die Cloud-Prinzipien sind grundlegende Konzepte, 
    welche das Cloud-Computing charakterisieren. 
    •   Internet    :   muss da sein 
    •   Service     :   möchte man nutzen 
    •   gemeinsam nutzbar     : für viele Per   sonen 
    •   skalierbar  :   wieviel RAM? 
    •   Virtualisierung

+	Single vs multi-tenant cloud: 
        Key differences and benefits

	Single-tenant cloud architecture provides a 
		dedicated environment where all hardware, 
            storage, and computing resources 
	are reserved for a single organization. 

	Multi-tenant cloud architecture shares the same 
		physical hardware and infrastructure among 
		multiple independent customers, 
		using logical isolation to keep each user's data secure and private.

>>>	K1.08:	Hybrid Cloud 
		ist eine IT-Umgebung, 
	die eine private Infrastruktur (Private Cloud oder lokale Server) mit 
	einer öffentlichen Cloud (Public Cloud) 	verbindet, 
	sodass Daten und Anwendungen zwischen beiden ausgetauscht werden können.
	Vorteile :
	Flexibilität: 
        Unternehmen nutzen die Skalierbarkeit der 
            Public Cloud bei Lastspitzen.
	Sicherheit: 
        Sensible Daten verbleiben geschützt in der Private Cloud.
	Kostenkontrolle: 
        Nur benötigte Zusatzressourcen in der Public Cloud werden bezahlt.

    Beispiel: 
        public:     Office365
        private:    Forschung&Entwicklung 
        community:  Verein 


+	Community Cloud 
		ist eine gemeinsame Cloud-Infrastruktur, 
		die von mehreren Organisationen oder Unternehmen 
		    mit ähnlichen Interessen, 
		Anforderungen oder Branchenstandards genutzt wird

	---	Merkmale und FunktionsweiseGemeinsame Nutzung: 
		Mehrere Parteien teilen sich eine IT-Infrastruktur, 
		um Kosten zu sparen und Daten sicher auszutauschen.
	Geschlossener Kreis: 
    	Im Gegensatz zu einer Public Cloud ist der Zugriff streng auf 
    	eine definierte 
	Gruppe (z. B. Behörden, Krankenhäuser oder Banken) beschränkt.
	Verwaltung: Die Verwaltung kann durch eine der 
		beteiligten Organisationen oder einen externen Dienstleister erfolgen.

>>>	K1.09:	multi-cloud
	Die Nutzung von Cloud-Diensten verschiedener Anbieter 
		(z. B. AWS und Google Cloud gleichzeitig), 
	um sich nicht an einen einzigen Provider zu binden und 
		spezifische Stärken der jeweiligen Anbieter zu nutzen.

>>> xpr ::  Server Virtualisierung [260903]

    === Type.1  :  "Bare-Metal Architecture"
	
    *	DireKt auf der HW
	Aufbau: Host(Hardware) - Hypervisor - VM - Gast-Os

	So funktioniert es:

	Physischer Server (Host): 
		Die echte Hardware mit CPU, 
            Arbeitsspeicher und Festplatten.
        *   es läuft kein Windows/Linux/etc...    

	Hypervisor: 
		Eine spezielle Software-Schicht, 
			die direkt auf der Hardware läuft. 
		Sie teilt die Ressourcen auf und trennt die VMs voneinander.
        
	Virtuelle Maschinen (Gäste): 
		Jede VM verhält sich wie ein eigener, 
		echter Computer mit einem eigenen Betriebssystem und Anwendungen.

<	Die wichtigsten Vorteile
	Kosteneinsparung: 
		Weniger physische Hardware bedeutet weniger Strom, 
		weniger Platz im Rechenzentrum und geringere Anschaffungskosten.
	Bessere Auslastung: 
		Ein großer Server ist oft unterfordert. Virtualisierung 
		    bündelt die Last, weil sich mehrere virtuelle Server 
		    die Leistung teilen.
	Flexibilität und Tempo: 
		Neue Server lassen sich per Mauskollk in Minuten erstellen 
		    statt tagelang auf neue Hardware zu warten.
	Ausfallsicherheit: 
		Virtuelle Maschinen können im laufenden Betrieb 
		auf einen anderen physischen Server verschoben werden (Live-Migration).
	<:	VMware vSphere / ESXi
		Microsoft Hyper-V
		KVM / Proxmox
		Nutanix AHV

+   Bare Metal, Virtual Machines or Containers?
    https://www.cloud4c.com/blogs/bare-metal-vs-vms-vs-containers-ultimate-guide-to-modern-infrastructure-operations

    Bare Metal (Owning the House)
        Like owning a house from foundation to roof – 
            get direct access to all hardware resources, 
            customize every aspect of the server, 
            install any operating system, 
            and have full control over performance, 
            security, and configuration.

    Virtual Machine (Renting the Whole House)
        There is significant freedom without owning the infrastructure. 
        One can install software, modify settings, and run applications, 
        but the physical hardware is managed by the cloud provider - 
            just like a rental where the property owner 
            handles major structural changes.

    Container (Renting a Room in the House)
        Containers are lightweight, 
            portable environments that share the host OS-es kernel. 
        Considered more affordable and flexible, 
        and ideal for microservices and application deployment. 
        Like a room in a shared house, 
            there is limited access and shared resources.

>>> xpr ::  Gemini.$>   "Data Center Architecture" [260907]

+   Data Center Architecture encompasses the 
    integration of physical facility design, 
        computing infrastructure, network topologies, 
        and management software to form a scalable, high-availability platform.

1. Physical & Infrastructure Layer
    A facility relies on critical support systems to keep hardware running 
    safely and continuously:
    Power Systems: 
        Redundant power distribution units (PDUs), uninterruptible power 
        supplies (UPS), and backup diesel generators 
        (often deployed in $N+1$ or $2N$ redundancy configurations).  
    Cooling & Environmental Control: 
        Air-based cooling (Hot/Cold Aisle containment) and liquid cooling 
        solutions (direct-to-chip or immersion) 
        designed to handle high TDP workloads like AI/ML clusters.
    Security & Compliance: 
        Biometric entry controls, surveillance, and fire suppression 
        systems (e.g., clean agent gas systems).

2. Network Architecture  
    Modern data centers have shifted from legacy 3-tier models to  flat, 
    high-throughput topologies optimized for 
    server-to-server (East-West) traffic.

<<< xpr ::  Gemini.$<.  "Data Center Architecture".

+   Compliance 
    Was bedeutet Compliance und was gehört konkret alles dazu? 
    Compliance beschreibt, 
        dass ein Unternehmen sich verlässlich an geltende Gesetze hält, 
        interne Regeln beachtet und verantwortungsvoll handelt. 
    Dazu gehören z.B. Anti-Korruption, Datenschutz,

+   Layered Data Center Design typically follows:
    Core Layer – 
        High-speed Layer 3 backbone connecting aggregation modules 
        with no single point of failure.
    Aggregation Layer – 
        Integrates services like firewalls, load balancers,

    Access Layer – 
        Direct server connections (rack servers, blade servers) 
        with Layer 2/3 switching.

>>> xpr ::  SOA [260901]

	SOA steht im Bereich der Informationstechnik 
	für serviceorientierte Architektur (engl. service-oriented architecture)

Was ist eine Serviceorientierte Architektur (SOA)?

Definition: 
	in Architekturmuster, bei dem Softwarefunktionen als unabhängige, 
		 sich geschlossene Dienste (Services) organisiert werden.
Funktionsweise: 
	Die einzelnen Services erledigen bestimmte Aufgaben oder 
	Geschäftsprozesse und kommunizieren über ein Netzwerk miteinander.
Komponenten: 
	Ein Dienst wird von einem Anbieter bereitgestellt, 
	über ein Verzeichnis gesucht und von einer anderen Anwendung angefragt.
Vorteile: 
	Anwendungen sind flexibler, 
	Bausteine lassen sich leichter austauschen und der Code kann in 
	anderen Programmen wiederverwendet werden.

    A storage area network (SAN) or storage network is a computer network 
        which provides access to consolidated, 
        block-level data storage. 
    SANs are primarily used to access data storage devices, 
        such as disk arrays and tape libraries from servers so that 
        the devices appear to the operating system as direct-attached storage. 
    A SAN typically is a dedicated network of storage devices not accessible through the local area network (LAN).
    Although a SAN provides only block-level access, 
        file systems built on top of SANs do provide file-level access and 
        are known as shared-disk file systems.
    Newer SAN configurations enable hybrid SAN[1] and allow traditional 
    block storage that appears as local storage 
        but also object storage for web services through APIs.

        To access the SAN, so-called SAN servers are used, 
        which in turn connect to SAN host adapters. 
    Within the SAN, a range of data storage devices may be interconnected, 
    such as SAN-capable disk arrays, JBODs and tape libraries.

+   A Service Level Agreement (SLA) is a formal, 
        legally binding or operational contract 
            between a service provider and a customer. 
    It defines the specific quality, availability, 
        and responsibilities expected during the service delivery, 
        along with remedies or penalties if those standards are not met.

+   Core Components of an SLA
 
    Component	    :   
        1.  Scope & Services          
        2.  Performance Metrics        
        3.  Service Provider Commitments
        4.  Penalties & Credits
        5.  Customer Responsibilities
        
    Description	    :   
        1.  Defines exactly what services are provided 
            and supported.
        2.  Quantifiable indicators used to measure service quality.
        3.  Objectives the provider guarantees to maintain.
        4.  Financial or operational compensation if SLA targets are missed.
        5.  Duties required from the client to uphold the agreement.
                    
    Example:    
        1.  "24/7 Monitoring and Management of Cloud Infrastructure."
        2.   Uptime, Latency, Throughput, Response Time.
        3.  "99.9% system uptime per calendar month."
        4.  "10% bill credit if uptime falls below 99.0%."
        5.  "Providing timely access to internal server logs during incidents."
    
    Key Performance Metrics:    
        •   Uptime / Availability: 
            Percentage of time services are operational 
                (e.g., 99.9% uptime allowing a maximum of ~43 minutes 
                    of monthly downtime).
        •   Mean Time to Respond (MTTRsp): 
            Time taken to acknowledge a critical issue after it is logged.
        •   Mean Time to Resolve (MTTR): 
            Average time elapsed from issue reporting to resolution.
        •   Response Time & Latency: 
            Speed at which a application or system responds to user requests.

    Types of SLAs
        •   Customer-Based SLA: 
            Tailored to an individual customer covering all services 
            they use (e.g., an enterprise software contract).
        •   Service-Based SLA: 
            Standard agreement offered to all customers using 
            a specific service 
            (e.g., standard AWS or Microsoft 365 uptime guarantees).

    Multi-Level SLA: 
        Layered structure addressing global corporate rules, 
            specific customer requirements, 
                and distinct service tiers within one document.

Common SLA Levels (The "Nines" of Availability)

| Availability % | Allowed Downtime / Month |
+----------------+--------------------------+
| 99% ("Two 9s") | ~7 hours 18 minutes      |
| 99.9% ("Three")| ~43 minutes 49 seconds   |
| 99.99% ("Four")| ~4 minutes 23 seconds    |
| 99.999% ("Five")| ~26 seconds              |

    ?   What are the key benefits of using a VPN combined with MPLS?

>>> xpr ::  Gemini.$>   "benefits of using VPN combined with MPLS"


    Combining a VPN (Virtual Private Network) with 
        MPLS (Multiprotocol Label Switching) 
        is a common hybrid WAN strategy. 

    MPLS provides high performance, reliability, 
        and strict Quality of Service (QoS), 
        while a VPN provides flexibility, 
            cost efficiency, and strong encryption over the public internet.

    When integrated—often implemented via a Hybrid 
        WAN or SD-WAN architecture—you get the strengths of both 
        networking models:

1.  Cost Optimization

    Offloading Non-Critical Traffic: 
        MPLS bandwidth is expensive per megabit. 
        By routing less critical, high-volume internet 
        traffic or SaaS applications 
        (like Office 365 or video streaming) through secure VPN connections, 
        you free up expensive MPLS capacity for mission-critical apps 
        (like ERPs or core database access).

    Tiered Connectivity: 
        You can connect high-priority, 
        core data centers using MPLS, 
        while connecting remote or smaller branch offices 
        using significantly cheaper broadband or LTE VPNs.

2.  Enhanced Security & Encryption

    Data-in-Transit Protection: 
        Traditional MPLS networks are private,
        meaning they are isolated from the public internet, 
        but traffic within an MPLS cloud is generally not encrypted by default.

    End-to-End Encryption: 
        Overlaying an IPsec VPN on top of an MPLS link adds 
        strong cryptographic encryption (like AES-256). 
        This protects sensitive traffic against potential eavesdropping 
        if the service provider's network is compromised or 
        if traffic crosses carrier interconnects.

3. Redundancy & High Availability

    Seamless Failover: 
        Setting up a VPN alongside an MPLS circuit creates a 
        primary/backup path structure. 
        If an physical fiber cut or carrier outage disables the MPLS line, 
        traffic automatically reroutes over the encrypted VPN connection 
        across public internet providers, ensuring continuous uptime.

4. Rapid Remote Branch & User Onboarding

    Fast Deployment: 
        Provisioning a new MPLS link requires coordinating with 
    telecom carriers and can take weeks or months. 
    A site-to-site VPN over local broadband can be set up 
    in hours to get a remote site operational immediately.

    Hybrid Work Support: 
        MPLS only connects physical sites. 
        Remote, mobile, or work-from-home employees can 
        use client-based VPNs to connect securely into the enterprise network, 
        effectively extending the corporate MPLS domain to remote users.

5. SLA Guarantees Combined with Broad Reach

    Optimized Latency for Real-Time Apps: 
        MPLS offers guaranteed Service Level Agreements (SLAs) for jitter, 
        packet loss, and latency, making it ideal for 
        Voice over IP (VoIP) and live video conferencing.

    Global Footprint: 
        Where MPLS is unavailable or cost-prohibitive 
        (e.g., distant international regions), 
        VPN over public internet fills the geographical gaps 
        without sacrificing connectivity.

    The "CIA triad" of confidentiality, integrity, 
        and availability sits at the heart of 
            many information security standards.[1] 
    The concept was introduced in the Anderson Report in 1972 and 
    later repeated in The Protection of Information in Computer Systems. 
    The abbreviation was coined by Steve Lipner around 1986.[2]
    The triad is used in information-security standards and guidance, 
    including the ISO/IEC 27000 family of standards and the 
    NIST Cybersecurity Framework. ISO/IEC 27000 defines information 
    security as the preservation of confidentiality, 
    integrity and availability of information, 
    while other frameworks use the three concepts as part 
    of wider approaches to managing cyber and information-security risk.

+   BSI Smartphone 
    Ein besonderes Risiko stellt in vielen Fällen der Zugang 
        via Smartphone dar. 
    Werden die Zugangsdaten in der App des Dienstes gespeichert, 
        genügt ein bloßes Aufrufen der App, 
        um auf die Cloud zuzugreifen. 
    Was auf der einen Seite praktisch ist, 
        bedeutet andererseits, 
        dass möglicherweise auch Schadprogramme auf 
            dem Smartphone leichten Zugriff auf die Daten in der Cloud haben. 
    Wenn das Smartphone durch Verlust oder Diebstahl in falsche Hände gerät, 
        sind die Cloud-Daten nur so sicher, 
        wie der Zugriff auf das Smartphone geschützt ist. 
    Wer also beispielsweise sein Smartphone 
        nur mit einer vierstelligen PIN schützt, 
        legt die Hürde recht niedrig. 
    Außerdem ist in der Regel nicht garantiert, 
        dass die verwendeten Apps die Daten verschlüsselt übertragen. 
    Anders als bei der Benutzung 
        moderner Internet-Browser werden Benutzer hier i.d.R. 
    nicht auf die Risiken einer 
        unverschlüsselten Verbindung hingewiesen. 
    Die Benutzung eines Smartphones in unsicheren Hotspots 
        kann also mit Sicherheitsrisiken verbunden sein.

+   Total Cost of Ownership (TCO) and Return on Investment (ROI) 
    are complementary financial metrics used to evaluate 
        capital allocations, 
        software purchases, and infrastructure investments.
    In short: TCO calculates what an investment costs, 
        while ROI calculates what an investment yields.

+   Core Definitions [Gemini]

!   key:TCO     Total Cost of Ownership
    A holistic accounting methodology 
        that captures all direct and indirect, 
    upfront and ongoing costs associated with purchasing, 
        deploying, operating, and retiring an asset 
            over its entire lifecycle.

!   key:ROI     Return on Investment
    A profitability ratio that measures 
        the financial gain or efficiency of an investment 
            relative to its total costs.

!   key:CAPEX   Capital Expenditures 
    are funds used by a company to acquire, upgrade, 
        and maintain physical assets such as 
            property, plants, buildings, technology, or equipment. 
    These expenditures are made to expand 
        operations or maintain current scope over 
        a long-term period (typically longer than 1 financial year).
    *   Welche langfristige Investitionen ?

    Key Characteristics of CAPEX
    Long-Term Asset Creation: 
        Adds value to fixed assets or extends their 
            useful lifespan 
        (e.g., buying a warehouse, upgrading factory machinery, or 
            purchasing enterprise servers).
    Capitalized, Not Expensed: 
        CAPEX costs are not fully deducted from revenue on the 
            income statement in the year they are spent. 
        Instead, they appear on the Balance Sheet as an asset.
    Depreciation & Amortization: 
        The expense is gradually written off over 
        the asset's useful life via Depreciation 
        (for tangible assets) or 
        Amortization (for intangible assets like patents or 
        proprietary software).

!   key:OPEX    Operational Expenditure   
    OPEX stands for Operational Expenditures (or Operating Expenses). 
        It refers to the ongoing day-to-day costs that a 
        business incurs to keep its core operations running.
