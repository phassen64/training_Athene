$   fault vs error vs failure

    While often used interchangeably in casual 
        conversation, 
        fault and error represent distinct 
        stages in a cause-and-effect chain 
    within systems, software, and engineering:

    •   fault 
        definition:    
            The underlying cause, defect, 
                flaw, or mistake in the system or code.
        key difference:    
            Cause (Static / Latent)
        example:
            A programmer writes '>' instead of '>=' 
            in a conditional loop.
    
    •   error    
        definition:
            The incorrect internal state resulting 
                from a fault during execution.
        key difference:
            Manifestation (Dynamic)
        example:
            A variable holds a value of 10 
                when it should be 11.

    •   failure 
        definition:
            The observable incorrect behavior 
                visible to the end user or external system.
        key difference:
            Effect (External Result)
        example:
            The application crashes or produces an 
                incorrect final total on screen.

=== m:  [1.6]   Infrastructure as Code (IaC) Basics with Terraform

+   What is IaC ?

    01  IAC manages infrastructure thorough code, 
        not manual    processes            
   
    02  developers define servers. networks, storage 
        and cloud seources 

    03  using configuration files are version-controlled,
        resusable and automated 
        
        
+   How IaC works ?

    1.  IaC automates infrastructure through machine-readable code    
    2.  it enbales scalability, repeatable and faster deployment with 
        less manual effort
        
+   IaC workflow 
    step1:  developer define infrastructure using 
                scripts, templates or policies 
    step2:  the files are stored in a version control system 
                for collaboration, version tracking, auditing and rollback
    step3:  tools like 
            •   Terraform 
            •   Ansible 
            •   Chef
            •   Puppet
            •   AWS CloudFormation
    step4-6:
            •   servers 
            •   databases 
            •   storage 
            •   networks
            •   cloud services 
            actions:
                create & update & remove

+   example 
    Terraform
        provider "aws" {        *   welcher CSP 
        region = "us-west-2"    *   welcher region 
    }
    resource "aws_instance" "example" {
        ami           = "ami-0c55b159cbfafe1f0"     *   instance id 
        instance_type = "t2.micro"      *   welche provisioning model
        tags = {
            Name = "IaC-Managed-Instance"
        }
    }
               

+   Benefits of IaC 
    ... delivers consistent environments
    ... encourages reusable modules 
    ... simplifies disaster recovery by recreating infrastructure from code
    
+   Approaches of IaC 
    1.  declarative 
        •   Terraform 
        •   AWS CloudFoundation 
        •   Kubernet YAML 
        focus : "what the infrastructure should look like"
        
    2.  imperative
        •   Ansible 
        •   bash scrips 
        •   powershell scripts
        focus : "how to achieve the desired state"

    •   Wiederholbarkeit: 
        Sie können dieselbe Konfiguration beliebig 
            oft in Test-, Staging- und Produktionsumgebungen ausrollen.

    •   Versionskontrolle: 
        Infrastruktur-Code wird wie Anwendungscode in 
            Git gespeichert, nachvollziehbar geändert und per Rev

    •   Linear Transformations
        Operations that change the position, size,

    •   Systems of Linear Equations
        Sets of equations solved simultaneously using matrix methods.

    Wenn du eine Zahl $a$ mit ihrem Kehrwert 
        A * A **-1 = A**-1 * A = I multiplizierst, erhältst du 1. 
    Bei Matrizen ist das Prinzip analog: 
        Multiplizierst du eine quadratische Matrix $A$ mit ihrer inversen Matrix $A^{-1}$, 
    erhältst du die Einheitsmatrix $I$ (die Matrix, 
    die auf der Hauptdiagonale Einsen und sonst nur Nullen hat).
    $$A \cdot A^{-1} = A^{-1} \cdot A = I$$

+   Data Visualization
    ~ is the graphical representation of data using 
        charts, graphs, and plots. 
    It helps analysts and decision-makers understand
        complex information quickly and effectively.

+   Benefits of Data Visualization
    *   Simplifies large datasets.
    *   Identifies trends and patterns easily.
    *   Detects anomalies and outliers.
    *   Improves communication of insights.
    *   Supports better decision-making.


+   Common Visualization Techniques

    •   Bar Chart: 
        A bar chart uses rectangular bars to compare values across 
            different categories. 
            The length or height of each bar represents the magnitude 
            of the corresponding value.
        Use: Category comparison, 
            ranking products, and performance analysis.
        Example: Comparing sales of laptops, 
            smartphones, and tablets in a retail store.

    •   Pie Chart: 
        A pie chart represents data as slices of a circle, 
            where each slice shows the proportion of a category 
        relative to the whole.
        Use: 
            Showing percentage distribution and composition of data.
        Example: 
            Displaying the market share of different smartphone brands.

    •   Line Chart: 
        A line chart connects data points using lines to 
            show trends and changes over time.
        Use: 
            Trend analysis, forecasting, and time-series data visualization.
        Example: 
            Monitoring monthly revenue growth of a company throughout the year.

    •   Area Plot: 
        An area plot is similar to a line chart but fills the 
            area beneath the line, 
            emphasizing the magnitude of change over time.
        Use: 
            Visualizing growth, cumulative totals, and trends.
        Example: 
            Showing cumulative website traffic across several months.


    •   Histogram: 
        A histogram groups numerical data into intervals (bins) and 
            displays the frequency of observations in each interval.
        Use: Understanding data distribution, spread, and skewness.
        Example: 
            Analyzing the distribution of student examination scores.

    •   Scatter Plot: 
        A scatter plot displays individual data points to reveal 
            relationships between two numerical variables.
        Use: 
            Correlation analysis, trend identification, and 
                outlier detection.
        Example: 
            Examining the relationship between advertising expenditure 
            and sales revenue.

    •   Box Plot: 
        Box Plot: 
            A box plot summarizes the distribution of data using quartiles 
            and highlights outliers.
        Use: 
            Detecting outliers and understanding data spread.
        Example: 
            Comparing salary distributions across different departments.

    •   Heat Map: 
        A heat map uses colors to represent data values or 
            correlation strengths between variables.
        Use: Correlation analysis and pattern identification.
        Example: 
            Visualizing correlations among features in a 
            machine learning dataset.

    •   Real-Time Collection
        ~ is a method of data collection in which data is captured,

    •   Scheduled data transfer instead of continuous flow

    •   Efficient for large volumes of data
    •   Reduces system load during collection
    •   Easy to schedule and manage

    Limitations
    •   Delayed insights (high latency)
    •   Not suitable for time-sensitive applications

    Note: 
        Batch collection 
            is suitable when real-time processing is not required and 
            efficiency is prioritized over speed. 
        It is commonly used for large-scale, periodic data handling.

    •   Continuous and instant data capture
    •   Live monitoring of systems and events
    •   Streaming data processing without delay

    Advantages
    •   Immediate insights and responses
    •   Suitable for critical and alert-based systems
    •   Supports adaptive and dynamic decision-making

    Limitations
    •   Higher infrastructure and processing cost
    •   Complex system design and maintenance
    •   Requires continuous system availability

    Note: 
        Real-time collection 
            is used when immediate response and 
            up-to-date information are essential, 
        especially in dynamic environments.

=== m:  [3.2]   Big Data Technologies

    Big Data technologies are designed to

+   Apache Spark Overview:
    url:    https://spark.apache.org/

    ~ is a fast, 
        open-source distributed computing engine designed 
        for large-scale data processing and analytics. 

    It enables parallel data processing across 
        clusters of computers and is widely used 
    for big data workloads, 
        real-time analytics, 
        and machine learning applications.

    Spark supports multiple widely used programming languages 
        (Python, Java, Scala, and R), 
        includes libraries for diverse tasks ranging 
            from SQL to streaming and machine learning.

+   Spark Components 

    •   Apache Spark Core 
            is the foundation of the framework. 
            It provides distributed processing, memory management, 
            task scheduling, and fault tolerance.

    •   Spark Streaming 
            enables real-time data processing from continuous 
                data streams.
            
    •   MLlib 
            provides machine learning algorithms for 
            predictive analytics and data mining.

    •   Spark SQL 
        supports SQL queries and processing of 
            structured data using DataFrames.

    •   GraphX is used for graph processing and network analysis.
    

+   Core Features of Apache Spark

    •   Stream Processing
        Spark supports real-time processing of streaming 
            data, enabling continuous analysis of incoming 
            data such as logs, sensor data, and live events.
    
    •   Speed
        Spark is designed for high-speed computation by processing 
        data in memory, making it significantly faster than 
        traditional disk-based systems.
    
    •   Lazy Evaluation
        Spark does not execute operations immediately. 
        Instead, it builds a logical execution plan and 
        runs computations only when required, improving optimization.
    
    •   In-Memory Processing
        Data is stored and processed in RAM instead of disk, 
        which reduces I/O operations and increases processing efficiency.
    
    •   Concise
        Spark provides simple and expressive APIs (Python, Scala, Java), 
        allowing developers to write less code for 
            complex data processing tasks.

+   Apache Spark Architecture

    The diagram illustrates the high-level architecture of

    *   Application: User program using Spark APIs.
    *   Driver (Spark Session):

    *   Cluster Manager

    *   Executors (Worker Nodes):
        Run tasks in parallel and store intermediate data.

--- s:  [3.4].Data Quality

+   Key Dimensions of Data Quality

    *   Accuracy: 
        Accuracy refers to how correctly data represents real-world 
            values or facts. Accurate data is free from errors and ensures reliable decision-making.

    *   Completeness: 
        Completeness indicates that all required data fields are present 
        and populated. 
        Missing information can lead to incomplete analysis and 
        inaccurate insights.
    
    *   Consistency: 
        Consistency ensures that data remains uniform across 
            different systems, databases, and applications. 
        Consistent data improves reliability and prevents conflicts.

    *   Validity: 
        Validity measures whether data conforms to predefined formats, 
            rules, and business constraints. 
        Valid data supports smooth processing and analysis.

    *   Timeliness: 
        Timeliness refers to the availability of current and 
            up-to-date data when needed. 
        Timely data enables faster responses and informed decisions.

    *   Uniqueness: Uniqueness ensures that each record is 
        distinct and free from unnecessary duplication. 
        Unique data reduces redundancy and improves data integrity.


--- s:  [3.4].Data Governance

    Data Governance is a structured approach to managing an 
        organization's data through defined 
            policies, processes, roles, and standards. 
   
    It ensures that data remains 
        accurate, consistent, secure, and accessible throughout its lifecycle. 
   
    By establishing clear ownership and accountability, 
        data governance helps organizations improve data quality, 
        maintain regulatory compliance, reduce risks, and support reliable decision-making.

    A data catalog provides

--- s:  [3.4].Versioning


    Data versioning is the process of 
        tracking, managing, and storing changes 
        made to datasets over time. 
    
    Similar to source code version control in software development, 
        data versioning enables organizations to maintain 
        multiple versions of data, track modifications, 
        and reproduce results using specific dataset versions.

    As data continuously evolves through updates, 
        corrections, and new records, 
        versioning helps ensure consistency, traceability, 
        and reliability across analytics, reporting, and AI workflows.


+   Concept of Data Versioning

    The diagram represents data versioning in ML systems as a 
        combination of Data +  Model + Code, 
    where each component evolves independently and 
    jointly affects system behavior.

    *   Data Versioning 
        ~tracks changes in schema, sampling over time, 
        and data volume to ensure reproducibility of training datasets.

    *   Model Versioning captures changes in algorithms, 
        retraining cycles, and experiments to manage model evolution.

    *   Code Versioning manages business logic updates, 
        bug fixes, and configuration changes affecting pipeline behavior.

+   Key Features of Data Versioning

    *   Change Tracking: 
        Records all modifications made to datasets, 
        including additions, updates, and deletions.

    *   Historical Snapshots: 
        Maintains previous versions of datasets for reference and recovery.

    *   Reproducibility:	
        Allows	analyst and	data scientists	to reproduce 
            reports, experiments, 
            and model results using the exact dataset version.

    *   Rollback Capability: 
        Enables restoration of earlier versions if errors 
        or data corruption occur.

    *   Collaboration Support: 
        Allows multiple users and teams to work on datasets 
        while maintaining version history.

    *   Auditability: 
        Provides a complete record of dataset changes for compliance 
        and governance purposes.


+   Types of Versioning 

    •   Snapshot-Based Versioning
        Stores complete copies of datasets at different points in time.
        Simple implementation; Easy recovery and restoration.
        High storage requirements.

    •   Incremental Versioning
        Stores only the changes made between dataset versions.
        Efficient storage utilization; Faster updates.
        More complex version management.

    •   Hybrid Versioning
        Combines snapshots and incremental changes to 
            balance storage and performance.
        Improved scalability; 
            Efficient version tracking; Balanced storage usage.
        More complex implementation and maintenance.

    *   Streams API:

        between topics.

    *   Connector API: 
        Integrates Kafka with external systems 
        (e.g., databases) using reusable source and sink connectors.

+   A serverless architecture is a cloud computing model 
    in which the cloud provider manages all underlying 
        infrastructure, including server provisioning, 
            scaling, maintenance, and resource allocation. 

    This enables developers to focus entirely on building and 
        deploying application code without worrying 
        about infrastructure management.

    *   The cloud provider automatically executes the 
        code in stateless compute containers that are 
        event-triggered, and fully managed by the provider.

    *   Developers are unaware of the complexity of 
        operating these servers, 
        which includes capacity planning, scaling, and server maintenance.

    
+   Working of Serverless Architecture:
    It executes functions on demand based on events, 
        without requiring users to manage servers or infrastructure.

+   Workflow of a Serverless Web Application Architecture
    *   A user interacts with the Web Application.
    *   The request is sent to the API Gateway.
    *   The Authorizer validates the user's identity and permissions.
    *   After successful authentication:
        o   Content-related requests are routed to the Content Service.
        o   User-related requests are routed to the User Service.
    *   Services access External APIs or the External Database as required.
    *   Results are returned through the API Gateway to the user.

+   Characteristics of Serverless Computing

    *   Hostless: 
        Developers do not manage servers, 
            as infrastructure is fully handled by the cloud provider.
    *   Elastic: 
        Resources automatically scale up or down based on application demand.

    *   Stateless: 
        Each function execution is independent and does 
            not retain previous state.

    *   Event-driven: 
        Functions are triggered automatically in response to 
            events or actions.

    *   Lego Blocks: 
        Applications are built using small, reusable, and 
            modular components.

    *   High Availability: 
        Built-in redundancy ensures applications remain accessible and reliable.

    *   Usage-based Cost: 
        Users are charged only for the actual compute time and 
            resources consumed.

--- v:  [5.1].  Transformer

    Transformer is an advanced neural network architecture in 
        Deep Learning designed to process sequential data using 
        a mechanism called self-attention, 
        allowing it to focus on the most relevant parts of the input simultaneously rather than sequentially 
        like RNNs. 

    This makes transformers highly efficient and powerful for 
        tasks involving language, text, and large datasets.


*   Self-Attention Mechanism: 
    This is the core innovation of the Transformer.
    o   It allows the model to focus on different words in a 
        sentence while processing a specific word.
    o   Each word "attends" to all other words to understand context 
        that helps capture relationships regardless of distance in the sentence.

*   Parallel Processing: 
    Unlike RNNs (which process sequentially), Transformers:

    o   Process all tokens simultaneously.
    o   This significantly speeds up training and makes them highly efficient 
        for large datasets.

*   Captures Long-Range Dependencies
    o   Understands relationships between words that are far apart in 
        a sequence.
    o   Solves the "long-term dependency" problem found in 
        traditional models like RNN/LSTM.

*   Scalable Architecture
    o   Can be scaled by increasing layers, attention heads, and model size.
    o   Works effectively with large datasets and compute resources.


+   Need for Transformer Models:

    Traditional models like RNNs (Recurrent{"wiederkehrend"} Neural Networks) 
        suffer from the vanishing gradient problem which leads to 
        long-term memory loss. 
    Transformer models were developed to overcome the limitations of 
        traditional sequence-processing networks and 
        provide more efficient language understanding. 
    The following table highlights the key reasons behind the adoption 
    of Transformer architecture in modern AI systems.

--- s:  [5.2].Self-Attention Mechanism

+   Figure. 5.2: Self-Attention Mechanism

    The diagram illustrates how the self-attention mechanism processes 
        a sentence to capture contextual relationships between words.

    Step-by-Step Process

    1.  Input Tokens: 
        The sentence "How are you doing?" 
            is split into tokens: How, are, you, doing, ?.

    2.  Word/Token Embedding: 
        Each token is converted into a vector representation (embedding) 
        that encodes semantic information.

    3.  Linear Projections: 
        The embeddings are multiplied with weight matrices to generate 
            three vectors.

    4. Attention Score Computation: Queries are multiplied with Keys 
        to compute attention scores, representing how much each word 
        should attend to others in the sequence.

    5.  Softmax Normalization: 
        The scores are passed through a softmax function to convert them 
            into normalized attention weights.

    6.  Weighted Value Aggregation: 
        The attention weights are multiplied with the Value vectors, 
        producing context-aware representations.

    7.  Hidden States Output: 
        The resulting vectors form the hidden states, 
        where each token representation now incorporates contextual 
        information from other tokens.


--- s:  [5.1].Transformer Architecture
    
    
    The figure illustrates the Encoder-Decoder Transformer Architecture, 
        the foundational framework behind modern 
    Natural Language Processing (NLP) and Generative AI models. 
    The architecture consists of two main components:

    *   Encoder, 
        which processes the input sequence and learns contextual 
            representations

    *   Decoder, 
        which generates the output sequence based on the encoded information.

    Unlike traditional sequential models, 
        Transformers use attention mechanisms to process all 
        tokens in parallel, 
        enabling efficient learning and better context understanding.

    Processes attention outputs through fully connected neural network 
        layers to learn complex patterns.

    •   Encoder Layer
        Consists of Multi-Head Attention, Add & Norm, 
            and Feed Forward layers that generate contextualized 
            representations of the input.

    •   Masked Multi-Head Attention
        Used in the decoder to prevent access to future tokens 
            during sequence generation.

    •   Decoder Layer
        Combines masked self-attention, encoder-decoder attention, 
        and feed-forward processing to generate outputs.

    •   Linear Layer
        Transforms decoder outputs into scores corresponding to the 
            vocabulary.

        Softmax Layer
        Converts scores into probability distributions and predicts the 
            most likely next token.


+   Working of Transformer Architecture 

    1. Input text 
       ~ is converted into embeddings and combined with 
            positional encodings.

    2.  Embeddings 
        Tokens are converted into numerical endings.
        
    3.  Positional Encoding 
        Positional encodings are added to preserve the order of tokens.

    4.  Encoder 
        The encoder processes the input and generates contextual 
            represenations.
    
    5.  Decoder (auto-regressive Generation)
        The decoder receives previously generated output tokens and
        and encoder outputs to predict the next token.
    
    6.  Select Next Token
        The token with the highest probability is selected.
        
    7.  Add to Output 
        The selected token is added to the output sequence.
        
    8.  Repeat 
        steps 5-7
    
    9.  Complete Output 
        The process stops when an end token (EOS) is generated.

+   Tokenization:
    ~ is the process of breaking down raw text into 
        smaller units called tokens,
        which serve as the basic inputs for Transformer models 
        and Large Language Models (LLMs). 
    Since AI models cannot directly understand human language, 
    tokenization converts words, subwords, characters, 
    or symbols into numerical representations that can be processed 
    by neural networks. 
    It acts as a crucial preprocessing step that bridges human-readable text and machine-readable data.

+   Tokens:
    ~ are the smallest units of text that a model processes. 
    Instead of reading entire sentences at once, 
    a language model breaks text into smaller pieces called tokens.

+   Tokens can represent:
    *   A word (e.g., cat, house)
    *   A subword (e.g., play + ing)
    *   A character (e.g., a, b, c)
    *   A punctuation mark (e.g., , . ? !)


+   Working of Tokenization:
    *   The input text is provided to the tokenizer.
    *   The tokenizer breaks the text into smaller units called tokens.
    *   Each token represents a meaningful word, subword, character, or symbol.
    *   The generated tokens are mapped to unique token IDs.
    *   The token IDs are converted into embeddings and 
        supplied to the Transformer model for training or inference.


+   Types of Tokens:

    Tokens are the basic units of text that an LLM processes. 
        Depending on how text is split, 
        there are different types of tokens:

    •   Word Tokens
        Splits text into complete words
        Simple and easy to understand
        Fails with rare or unknown words
        "The" "quick" "brown" "fox"

    •   SubWord Tokens
        Splits words into smaller meaningful units
        Handles new/complex words efficiently
        Slightly more complex than word tokens
        "un" "happy" "ness"

    •   Character Tokens
        Splits text into individual characters
        Works for any word or language
        Very long sequences, slower processing
        "H" "i" "!"

    •   Byte-Level Tokens
        Splits text into byte-level units
        Supports all languages & symbols
        Less intuitive, harder to interpret
        "Hello" -> 48.65.6c.6c.6f

    •   Special Tokens
        Reserved tokens for structure and control
        Helps model understand tasks & sequences
        Not part of actual text content
        <BOS> <EOS> <PAD> <UNK>

+   LLM (Large Language Model) 
    https://de.wikipedia.org/wiki/Large_Language_Model

    ~ is an AI system designed to 
    understand, generate, and work with human language. 
    It is trained on very large amounts of text data so it can 
    learn patterns in language such as grammar, meaning, context, 
    and relationships between words.

    Most modern LLMs are built using Transformer Architecture, 
        which enables the model to analyze relationships between words 
        in a sentence through mechanisms such as self-attention. 
    This allows LLMs to capture context even across long pieces of text.

    Ein Large Language Model (kurz LLM, englisch), 
        übertragen großes Sprachmodell, 
    ist die softwaretechnische Realisierung eines mathematischen 
        Sprachmodells, das sich durch seine Fähigkeit zur 
    Textgenerierung auszeichnet.[1][2] 
    Es handelt sich um ein sogenanntes computerlinguistisches Wahrscheinlichkeitsmodell, das statistische Wort- und 
    Satzfolge-Beziehungen aus einer Vielzahl von Textdokumenten durch 
    einen rechenintensiven Trainingsprozess erlernt hat und 
    diese Fähigkeiten seinem Benutzer oder einer anderen Anwendung 
    zur Verfügung stellt.[3]


+   Key characteristics of LLMs:
    *   Trained on massive text datasets
    *   Built using the Transformer architecture
    *   Understand context from surrounding words (context awareness)
    *   Generate text by predicting the next word/token
    *   Contain very large numbers of parameters
    *   Can perform multiple language tasks 
            (Q&A, writing, translation, coding)
    *   Generalize across unseen tasks using learned patterns
    *   Produce probabilistic, not fixed, outputs
    *   Do not possess true human-like understanding or reasoning


+   LLM Workflow

    *   Input Processing: 
        Raw text is received and prepared for model understanding.

    *   Positional Encoding: 
        Adds information about word order so the model understands 
        sequence structure.

    *   Self-Attention Computation: 
        Identifies relationships between words by assigning 
            importance (attention scores).

    *   Transformer Layers: 
        Multiple stacked layers refine 
        representations and deepen understanding of context.

    *   Contextual Understanding: 
        The model builds a meaningful representation of the input 
            based on learned relationships.

    *   Output Generation: 
        The model predicts and constructs the most relevant response 
        token by token.

    *   In-Context Learning: 
        Uses patterns from the current input context to improve 
        response relevance.

    *   Response Delivery: 
        Final generated text is presented as the output to the user.

=== m:  [5.3]   Prompt Engineering Techniques
    v:  [5.5]

    Prompt Engineering is the process of designing 
        clear, structured, and effective inputs (prompts) 
        to guide a Large Language Model (LLM) 
        to produce accurate, relevant, and useful outputs. 
    Since LLMs generate responses based on input instructions, 
        the quality of the prompt directly affects the quality of the output.

+   Importance of Prompt Engineering:
    *   Improves accuracy of responses
    *   Reduces ambiguity and errors
    *   Saves time by getting better results in one attempt
    *   Helps tailor outputs for specific project needs


+   Key Elements of an Effective Prompt:
    *   Clear Instructions: 
            Specify exactly what you want.
    *   Context: 
            Provide background information.
    *   Specific Output Format: 
            Tell the model how to structure the answer.
    *   Role Assignment: 
        Guide the model by assigning a role.


+   Common Prompting Techniques
    
    1.  Zero-shot prompting 

        involves asking the model to 
            perform a task without providing any examples. 
        The model relies solely on its pre-trained knowledge and 
            the instructions given in the prompt.

        Key Features:
        *   No training examples required.
        *   Fast and easy to implement.
        *   Suitable for straightforward tasks.
        *   Leverages the model's existing knowledge.


    2.  Few-Shot prompting

        Few-Shot Prompting is a prompt engineering technique 
            in which a Large Language Model (LLM) is provided 
            with a small number of examples before 
            being asked to perform a task. 
        These examples demonstrate the expected input-output pattern, 
            helping the model understand the task requirements 
            and generate more accurate responses.

        Unlike Zero-Shot Prompting, 
            which relies solely on instructions, 
            Few-Shot Prompting guides the model through examples, 
        improving performance on tasks that require specific formats, 
        reasoning patterns, or domain knowledge.

        Key Characteristics
        *   Uses a small number of examples (typically 2-10).
        *   Demonstrates the expected format and behavior.
        *   Improves consistency and accuracy.
        *   Requires no model retraining.
        *   Helps with structured and domain-specific tasks.

        Advantages:
        *   Higher accuracy than zero-shot prompting.
        *   Better handling of complex tasks.
        *   Produces more consistent outputs.
        *   Enables format control.
        *   Effective for specialized applications.

        Limitations:
        *   Requires carefully designed examples.
        *   Longer prompts increase token usage.
        *   Performance depends on example quality.
        *   Too many examples may increase costs and latency.


    3. Chain-of-Thought (CoT) Prompting

        Chain-of-Thought (CoT) Prompting is a prompt engineering technique 
            that encourages a Large Language Model (LLM) 
        to solve problems by generating intermediate reasoning steps 
            before producing the final answer. 
        Instead of directly providing an answer, 
            the model explains its thought process step-by-step, 
        improving performance on tasks that require logical 
        reasoning, calculations, decision-making, 
        and problem-solving.

        CoT prompting is particularly effective for complex tasks 
            where arriving at the correct answer requires 
            multiple reasoning steps.

        Key Features:

        *   Promotes step-by-step reasoning.
        *   Improves transparency of decision-making.  
        *   Enhances performance on complex tasks.

        Workflow
        
        *   Start Task: 
            The process begins when a user provides a task or problem 
                to the LLM.

        *   Receive Input/Question (Q): 
            The model receives the input question and identifies the objective.

        *   Break Down the Problem
            o   The problem is divided into smaller sub-problems or 
                intermediate steps.
            o   Key components, 
                    dependencies, and requirements are identified.

        *   Generate Step-by-Step Reasoning
            o   The LLM produces a sequence of logical reasoning steps.
            o   Each step builds upon the previous one to progress 
                toward a solution.

        *   Validate and Refine Reasoning
            o   The reasoning process is checked for logical consistency.
            o   Errors, gaps, or missing steps are corrected and refined.

        *   Derive Final Answer (A)
            o   The model combines all intermediate conclusions.
            o   A well-supported and justified final answer is generated.

        *   Output Answer with Reasoning
            o   The final response includes both the answer and 
                the reasoning process.
            o   This improves transparency, 
                explainability, and user understanding.

+   Comparison
    
    •   zero-shot prompting
        The model performs task without any examples.
        Input -> ChatBot -> Output

    •   few-shot prompting 
        The model receives a few examples before the task.
        examples -> ChatBot -> NewTask -> Output 
        
    •   chain-of-thought prompting 
        Question/Problem -> Intermediate/Reasoning Steps->Final Answer

=== m:  [5.4]   Generative Model Lifecycle


    Generative AI models such as 
        GPT, Gemini, Claude, Llama, and Mistral 
    are developed through a structured lifecycle that 
    transforms a general-purpose language model into a safe, 
    useful, and task-oriented AI system. 
    
    Understanding this lifecycle helps AI and Cloud Practitioners 
        appreciate how large language models (LLMs) are 
            trained, customized, and deployed in cloud environments.

+   lifecycle

    The lifecycle of a generative AI model typically consists of 
        three major stages:

    1.  Pre-training: 
        Learning general language and knowledge patterns from massive datasets.

    2.  Fine-tuning: 
        Adapting the model for specific tasks, domains, or business requirements.

    3.  Alignment (RLHF): 
        Ensuring the model produces helpful, safe,
            and human-aligned responses.


+   Reinforcement Learning from Human Feedback (RLHF)
    The most widely used technique is Reinforcement Learning from 
        Human Feedback (RLHF)

    1.  Step 1: 
        Human Evaluation: 
            Human reviewers assess multiple model-generated 
        responses and rank them according to quality, 
            usefulness, and safety.

    2.  Step 2: 
        Reward Model Training: 
        A reward model learns human preferences based on these rankings.

    3.  Step 3: 
        Reinforcement Learning: 
            The language model is optimized to maximize reward 
            scores using reinforcement learning techniques such as:

        *   Proximal Policy Optimization (PPO)
            -> ranking 

        *   Direct Preference Optimization (DPO)
            ? "top" or "flop"

        Outcome: 
            An Aligned AI Model that better follows instructions and 
            adheres{"haften,kleben,..."} to safety standards.

=== m:  [6.2]   Inference Optimization Techniques
    

+   Inference optimization techniques help organizations 
    serve more users efficiently while maintaining acceptable 
        model accuracy. 
    Three of the most widely used optimization techniques are 
        •   Quantization, 
        •   Batching, and 
        •   Caching. 
    Let's explore these in below section.


--- s:  [6.2].Quantization

+   Quantization is the process of reducing the 
    numerical precision of model weights and activations. 
    Instead of using high-precision data types such as 
        32-bit floating-point (FP32), 
    the model uses lower-precision formats such as 
        FP16, INT8, or INT4. 
    The goal is to lower the model's size and improve its 
        computing efficiency without sacrificing too much performance.

+   Quantization-Aware Training (QAT): 
    ~ is a technique 
        that simulates low-precision computations during training 
        to produce a highly accurate quantized model.

+   Post-Training Quantization (PTQ): 
    ~ is a technique that converts a fully trained model 
        to lower precision without retraining, 
        using a small calibration dataset.


--- s:  [6.2].Batching:

+   Batching is an inference optimization technique that processes 
        multiple input requests together as a 
        single batch 
    instead of handling each request individually. 
    By grouping inputs and executing them simultaneously, 
        batching improves hardware utilization, 
        increases throughput, 
        and reduces the overall cost of AI inference.

+   In cloud-based AI systems and Large Language Models (LLMs), 
    batching is commonly used to maximize 
        the efficiency of GPUs and AI accelerators, 
        which perform parallel computations more effectively 
        when processing multiple inputs at once.


+   Static Batching: 
    Groups a fixed number of requests into a batch before processing, 
        providing high throughput for predictable workloads.
    *   Requests are collected into fixed-size 
        batches before execution.
    *   The system waits until the predefined batch 
        size is reached.
    *   Provides high throughput and efficient GPU utilization 
        but may increase latency if requests arrive slowly.

+   Dynamic Batching: 
        Collects requests during a short time window and 
            processes them together, adapting the batch size 
                based on incoming traffic.

+   Continuous Batching: 
    Continuously adds new requests to an already running batch, 
        maximizing GPU utilization and minimizing latency.


--- s:  [6.3].Caching


+   Caching:
    ~ is a performance optimization technique that stores previously 
        computed data so it can be reused instead of being recomputed. 
    In LLM applications, 
        caching reduces latency, 
        lowers computational costs, 
        improves throughput, 
        and enhances 
    the user experience by avoiding redundant processing.

+   Vocabulary 
    vault.en :: Tresorraum.de 

+   Caching Workflow

    Step 1: User Query and Prompt
            *   The user submits a query or prompt to the LLM application.
            *   The application receives the request and prepares it for 
                    processing.

    Step 2: Check Cache
            *   Before invoking the LLM, 
                the application checks the LLM cache
                    (e.g., Redis or an in-memory cache).
            *   The cache is searched for a previously 
                stored response that matches the incoming prompt.

    Step 3a: Return Cached Response (Cache Hit)
            *   If a matching response exists in the cache 
                (a cache hit), 
                the application retrieves and returns it directly to the user.
            *   Since no model inference is performed,
                the response is delivered much faster while 
                    consuming minimal computational resources.

    Step 3b: Invoke the LLM (Cache Miss)
            *   If the requested response is not found in 
                    the cache (a cache miss), 
                    the application forwards the prompt 
                to the Large Language Model (shown as PaLM 2 in the diagram).
            *   The LLM generates a new response.
            *   The generated response is then stored in 
                the cache for future requests before being 
                    returned to the user.


+   Key Caching Techniques in LLMs

    •   Prefix Caching
        Stores and reuses the computed representations of common 
            prompt prefixes shared across multiple requests.
        Reduces repeated prompt processing, lowers inference time, 
            and improves throughput for applications with reusable prompts.

    •   KV (Key-Value) Caching
        Stores the attention key and value tensors generated 
            for previous tokens during autoregressive decoding, 
            allowing the model to reuse them instead of recomputing.
        Accelerates token generation, reduces GPU computation, 
            and enables efficient real-time text generation.

    •   Semantic Caching
        Retrieves cached responses for semantically similar queries 
            using embedding-based similarity instead of exact prompt matching.
        Improves response speed for similar queries, 
            reduces redundant inference, and lowers computational costs.

+   Generative AI (GenAI) applications consume 
    significant computing resources due

            inference, 
            storage, 
            networking,

        organizations may experience escalating cloud 
            expenses, 
            inefficient resource utilization, 
            and budget overruns. 
    Cost governance establishes 
        policies, 
        monitoring practices, 
        and optimization strategies 
    to ensure that GenAI workloads deliver business 
    value while maintaining financial efficiency.

+   Cost governance is the practice of 
        planning, 
        monitoring, 
        controlling, 
        and optimizing 
    the operational costs associated with 
        deploying and managing GenAI applications. 
    It involves tracking cloud resource usage, 
        allocating costs across 
            teams, 
            setting budgets, 
            and implementing 
    optimization techniques that 
    reduce unnecessary spending without 
    compromising application performance.

+   Cloud cost governance operates at a different level. 
        It focuses on control and intent. 
    It answers questions like:
    *   Who is allowed to create spend?
    *   Under what constraints?
    *   How are those constraints enforced as systems change?


+   Cost Governance Strategies

    Resource Monitoring
    Continuously monitor GPU utilization, 
        API usage, storage consumption, 
        and inference workloads to identify high-cost resources.


    Budget Management
    Define budgets, spending limits, 
        and cost alerts to prevent unexpected cloud expenditure.


    Right-Sizing Resources
    Allocate appropriate compute resources based on 
        workload requirements to avoid overprovisioning.

    Auto Scaling
    Automatically scale compute resources up or down 
        based on application demand to minimize idle infrastructure costs.


    Token Optimization
    Optimize prompts, reduce unnecessary context, 
        and control output length to minimize token usage 
            and inference costs.

    Model Selection
    Use smaller or distilled models for routine tasks and 
        reserve larger models for complex workloads to optimize costs.

    Caching
    Store frequently requested responses to reduce repeated inference 
        and lower API costs.

    Storage Lifecycle Management
    Move infrequently accessed datasets and logs to 
        lower-cost storage tiers to reduce storage expenses.


    Cost Allocation
    Tag cloud resources and allocate costs to departments, 
        projects, or business units for better financial accountability.


    Continuous Optimization
    Regularly review usage reports, remove unused resources, 
        and optimize infrastructure to maximize cost efficiency.

--- s:  [7.3].Performance Drift Detection


+   Performance Drift Detection:
    ~ is the process of identifying when a  deployed model's 
        •   <predictive performance> declines compared to its 
        •   <expected performance>. 
    Drift occurs because the 
        statistical properties of the data or 
        the relationship between inputs and 
            outputs change over time.


+   Types of Drift.A
    Model drift occurs when 
        a)  changes in data or 
        b)  underlying relationships 
    reduce the performance of a deployed machine learning model.


+   Types of Drift.B
    
    *   Data Drift (Covariate Drift): 

        Occurs when the distribution of input features 
        changes while the relationship between inputs 
        and outputs remains unchanged.

        Example: 
            A recommendation system trained on desktop 
            users begins receiving mostly mobile user data.

    *   Concept Drift: 
        Occurs when the relationship between 
            input features and the target variable changes, 
        causing the model's learned patterns to become outdated. 
        This often requires model retraining or updating.

        Example: 
            Customer purchasing behavior changes after 
                a <major festival> or <economic downturn>.

    *   Prediction Drift: 
        Occurs when the distribution of model 
            predictions changes significantly.

        Example: 
            A fraud detection model 
            suddenly classifies most transactions as 
            "low risk".

    *   Label Drift: 
        Occurs when the distribution of target labels changes.

        Example: 
            The percentage of fraudulent transactions increases 
                due to new cyberattack techniques.

Module 8: Retrieval-Augmented Generation (RAG)
===============================================================================

Retrieval-Augmented{"erweitern,steigern"} Generation (RAG) is a powerful 
    AI framework that enhances the capabilities of 
    large language models (LLMs) by combining them 
    with external knowledge retrieval mechanisms. 

Instead of relying solely on pre-trained knowledge, 
    RAG retrieves relevant information from structured and 
    unstructured data sources at query time and 
incorporates it into the generation process, 
enabling more accurate, up-to-date, and context-aware responses. 

This approach addresses common limitations of LLMs, 
such as hallucinations, outdated knowledge, 
    and lack of domain-specific expertise, 
    making RAG an essential technique for building reliable 
enterprise AI applications, 
intelligent assistants, and knowledge management systems.

+   Why RAG?
    Traditional LLMs have several limitations:
    *   Knowledge is limited to the data used during model training.
    *   Models cannot access newly added or frequently changing information.    
    *   Responses may contain hallucinations or incorrect facts.  
    *   Fine-tuning models for every knowledge update is 
        expensive and time-consuming.
    RAG addresses these challenges by retrieving 
        relevant information from external knowledge repositories 
        before generating responses.


+   RAG Architecture:
    ~ is the structural framework that integrates information 
        retrieval with large language models (LLMs) 
        to generate accurate, context-aware, 
        and knowledge-grounded responses. 
    It defines the end-to-end workflow and key components involved 
        in retrieving relevant information from 
        external knowledge sources and using it 
        to enhance the response generation process.


+   RAG Architecture workflow
    The figure illustrates the online workflow of a 
        Retrieval-Augmented Generation (RAG) architecture, 
        where an LLM generates responses 
    by retrieving relevant information from an 
        external knowledge base instead of relying only 
        on its pre-trained knowledge.

    Step 1: User Query: 
            The client submits a question to the RAG framework.

    Step 2: Semantic Retrieval

            *   The framework converts the query into an 
                embedding and performs a semantic search on the 
                vector database.

            *   Relevant information is retrieved from 
                indexed original and newly added documents.

    Step 3: Prompt Augmentation

            *   The retrieved context is combined with 
                the user's query to create an augmented prompt.
            *   The prompt is sent to the Large Language Model (LLM).

    Step 4: Response Generation
            *   The LLM generates a context-aware response using 
                the retrieved information.
            *   The framework post-processes the 
                response (e.g., formatting, validation) before 
                returning it to the user.


+   Core Components of RAG System:

    A RAG system consists of several(4) interconnected components 
        that work together to retrieve relevant information from external knowledge sources and generate accurate, context-aware responses. 
    Each component plays a specific role in ensuring efficient retrieval, effective prompt construction, 
        and reliable response generation.

    •   Retriever
        Searches the knowledge base using semantic search to 
            identify the most relevant information for a user's query.
        Retrieves contextually relevant document chunks{"Stück/Klumpen"} 
            from the vector database.

    •   Generator
        Receives the retrieved context and the user's query to 
        generate responses using a Large Language Model (LLM).
        Produces accurate, coherent, and context-aware responses.

    •   Knowledge Base
        Stores structured and unstructured organizational data, 
            such as documents, manuals, FAQs, databases, and web content.
        Serves as the primary source of knowledge for information retrieval.

    •   Integration Layer
        Coordinates interactions between the retriever, 
            knowledge base, and generator while managing workflows and APIs.
        Orchestrates retrieval, prompt construction, 
            response processing, and system integration.


+   Advantages of RAG Architecture

    •   Improved Accuracy & Reduced Hallucinations
        Grounds responses in retrieved information,

    •   Access to Up-to-Date Information
        Retrieves the latest knowledge without retraining the LLM.

    •   Enhanced Contextual Understanding
        Uses relevant context to generate more meaningful responses.

    •   Increased Transparency & Explainability
        Supports responses with retrieved sources, improving trust.
    
    •   Customization & Domain Specificity
        Leverages domain-specific knowledge for specialized applications.
    
    •   Reduced Training Costs
        Updates the knowledge base instead of retraining the model, 
            saving time and cost.

=== m:  [8.2]   Vector Databases and Embeddings


+   Vector databases and embeddings form the foundation 
        of Retrieval-Augmented Generation (RAG) systems. 
    Embeddings convert textual information into numerical vectors 
        that capture semantic meaning, 
        while vector databases store and retrieve these vectors 
        efficiently to enable fast and accurate semantic search. 


--- s:  [8.2].Embeddings

+   Embeddings are dense{"dicht,dumm"} numerical vector 
    representations of text, 
    images, or other data generated using machine learning models. 
    Unlike keyword-based representations, 
        embeddings capture the semantic meaning and 
        contextual relationships between pieces of information.
    
    For example, the sentences:   
        *   "The patient has a fever."
        *   "The person is experiencing a high temperature."
    have different words but similar meanings. 
    
    An embedding model generates vectors that are close together 
    in the vector space, enabling semantic retrieval.


+   Key Characteristics:
    *   Represent data as high-dimensional vectors.
    *   Capture semantic similarity instead of exact keywords.
    *   Generated using pre-trained embedding models.
    *   Used for semantic search, recommendation systems, clustering, and RAG.

+   Workflow of Vector Embeddings

    *   Multi-modal Input: 
        Images, documents, and audio are provided as 
            input to the embedding model.

    *   Embedding Model: 
        The model extracts semantic features and converts each 
            input into a fixed-length numerical vector (embedding).

    *   Vector Representation: 
        Each object is represented as a dense vector 
        (e.g., [0.6, 0.3, 0.1, ...]) that captures its meaning.

    *   Vector Space Mapping: 
        The embeddings are placed in a high-dimensional vector space.

    *   Semantic Clustering: 
        Objects with similar meanings are positioned close together, 
        while dissimilar objects are farther apart.

    *   Similarity Search: 
        Distance metrics such as Cosine Similarity, Euclidean Distance, 
        or Dot Product are used to identify the nearest vectors.

--- s:  [8.2].Vector Databases

    https://en.wikipedia.org/wiki/Vector_database

+   Vector Databases:
    A vector database is a specialized database designed to store, 
        index, and retrieve vector embeddings efficiently. 
    It performs similarity searches to find the most relevant 
        vectors based on semantic closeness, 
        making it an essential component of RAG systems.

+   Functions of a Vector Database

    *   Stores Vector Embeddings: 
        Stores high-dimensional vector embeddings along with 
            their associated metadata for efficient organization and retrieval.

    *   Performs Similarity Search: 
        Finds the most semantically similar vectors 
            using similarity metrics such as Cosine Similarity, 
            Euclidean Distance, or Dot Product.

    *   Supports Metadata Filtering: 
        Refines search results by applying filters based 
            on metadata such as category, source, date, or tags.

    *   Enables Efficient Indexing and Retrieval: 
        Uses optimized indexing techniques, 
        such as Approximate Nearest Neighbor (ANN), 
        to perform fast vector searches.

    *   Handles Large-Scale Vector Data: 
        Efficiently manages and retrieves millions or billions 
            of high-dimensional vectors with low latency, 
            making it suitable for enterprise-scale AI applications.

=== s:  [8.3].Advanced Chunking

+   ~ is the process of intelligently dividing 
        large documents into meaningful and context-preserving chunks 
    instead of using fixed-size text segments. 
    Better chunking improves retrieval accuracy by 
        ensuring that relevant information remains together.


+   Process of ~

    1   Semantic Chunking: 
        The document is divided into meaningful chunks 
            that preserve contextual information.

    2   Embedding Storage: 
        Each chunk is converted into a vector embedding and 
        stored in the vector database.

    3   Query Embedding: 
        The user's query is converted into an embedding for semantic search.

    4   Similarity Search: 
        The vector database retrieves the top-k most relevant chunks 
        based on semantic similarity.

    5   Response Generation: 
        The retrieved chunks are combined with the prompt and 
        passed to the LLM, which generates a context-aware response.


+   Types of ~


    •   Semantic Chunking
        Splits documents based on semantic meaning instead of 
            fixed character or token count, 
            grouping related sentences into coherent chunks.

    •   Recursive Chunking
        Breaks documents hierarchically 
            (sections ? paragraphs ? sentences) 
        while maintaining the document structure.

    •   Sliding Window Chunking
        Generates overlapping chunks so that adjacent chunks 
        share common content.

    •   Metadata-Aware Chunking
        Associates each chunk with metadata such as title, 
        author, page number, section, or source.


=== s:  [8.3].HyDE (Hypothetical Document Embeddings)

+   ~ is an advanced retrieval technique in which the 
    LLM first generates a hypothetical answer 
        or document for the user's query. 
    This generated text is then converted into an embedding and 
        used to retrieve semantically similar documents from 
        the vector database.
    Instead of embedding the user query directly, 
        HyDE embeds the generated hypothetical document, 
        often improving retrieval for ambiguous or complex queries.

+   Why is HyDE needed?

    HyDE is used to improve retrieval quality when a 
        user's query is short, ambiguous, or lacks sufficient context. 
    Instead of directly searching with the original query, 
    an LLM first generates a hypothetical answer or document, 
    which is then converted into an embedding. 
    This richer embedding is used to retrieve more relevant documents 
    from the vector database.


=== s:  [8.3].GraphRAG:

+   GraphRAG extends traditional RAG by incorporating knowledge 
        graphs to capture relationships between entities 
        such as people, organizations, documents, products, and events. 
    Instead of retrieving isolated document chunks, 
        GraphRAG retrieves connected information 
            based on relationships, 
    enabling deeper reasoning and multi-hop question answering.


+   Working of GraphRAG

    *   Indexing: 
        Documents from the text corpus are converted into a knowledge 
        graph containing entities and relationships. 
        Malicious or noisy documents may pollute the knowledge base.

    *   User Query: 
        The user submits a query (x) to the GraphRAG system.

    *   Semantic Retrieval: 
        GraphRAG performs semantic search over the knowledge graph 
        to retrieve the most relevant graph context (z).

    *   Prompt Construction: 
        The retrieved context is combined with the user query 
        to create an enriched prompt.

    *   LLM Generation: 
        The prompt is passed to the LLM, 
        which generates a context-aware response (y).

    *   Response Delivery: 
        The generated response is returned to the user.

    3. Context Precision: 
        measures how much of the retrieved context is actually 
        useful for generating the answer.
    4. Context Recall: 
        evaluates whether the retrieval system fetched 
        all the information required to answer the query completely.


=== m:  [8.5]   Cloud-native vector search services


+   Cloud-native vector search services are fully managed databases or 
        cloud services designed to store, index, 
    and retrieve high-dimensional vector embeddings. 
    They support semantic similarity search by comparing vectors 
        instead 
    of relying on exact keyword matching.

    Unlike self-hosted vector databases, 
        cloud-native services automatically handle 
        infrastructure management, scaling, backups, security, 
    and software updates.


+   Importance of Cloud-Native Vector Search Services

    *   Fast ANN Search: 
        Performs sub-second similarity searches using 
        Approximate Nearest Neighbor (ANN) algorithms 
        for rapid retrieval.

    *   Automatic Scaling: 
        Dynamically scales compute and storage resources 
        to handle growing data and user traffic.

    *   Managed Service: 
        Provides built-in maintenance, backups, high availability, 
        and monitoring with minimal operational overhead.

    *   Secure Cloud Environment: 
        Ensures enterprise-grade security through encryption, 
        IAM, private networking, and compliance support.
    
    *   LLM Integration: 
        Seamlessly connects with Large Language Models (LLMs) 
        to  power Retrieval-Augmented Generation (RAG), 
        semantic search, and AI assistants.


+   Cloud-Native Architecture

    *   Containers: 
        Containers package applications with all their dependencies, 
        ensuring consistent execution across different environments. 
        They enable portability, efficient resource utilization, 
        and rapid deployment.

    *   Microservices: 
        Applications are divided into small, 
            independent services, each responsible for 
            a specific function. This modular approach 
            improves scalability, flexibility, and fault isolation.

    *   DevOps: 
        DevOps integrates development and operations through 
        collaboration and automation. 
        It accelerates software delivery while improving 
        reliability, monitoring, and operational efficiency.

    *   CI/CD (Continuous Integration/Continuous Deployment): 
        CI/CD automates code integration, 
            testing, and deployment, enabling faster 
            software releases with fewer errors and consistent application updates.


+   Popular Cloud-Native Vector Search Services


    •   Azure AI Search
        Microsoft's managed search service with built-in vector search.
        Hybrid search, semantic ranking, Azure OpenAI integration.

    •   Amazon OpenSearch Service
        AWS-managed search service supporting vector 
            similarity search.
        ANN search, real-time indexing, auto scaling.

    •   Google Vertex AI Vector Search
        Google Cloud's managed vector search platform for AI applications.
        Low-latency search, Vertex AI integration, scalable indexing.

    •   Pinecone
        Fully managed vector database for AI and semantic search.
        Fast retrieval, metadata filtering, automatic scaling.

    •   Weaviate Cloud Service
        Managed vector database with semantic and hybrid search.
        Hybrid search, graph support, LLM integration.

    •   MongoDB Atlas Vector Search
        Vector search integrated into MongoDB Atlas.
        Hybrid queries, automatic indexing, cloud scalability.

    •   Elasticsearch
        Distributed search engine with vector search capabilities.
        Dense vectors, hybrid search, real-time analytics.
