9.1 Full Fine-Tuning vs. Parameter-Efficient Fine-Tuning (PEFT)

Foundation models and Large Language Models (LLMs) are pre-trained on massive datasets and can perform a wide range of tasks. However, enterprise applications often require these models to understand domain-specific terminology, business processes, and organizational knowledge. Fine-tuning adapts a pre-trained model to a specific task by training it on domain-specific data. Depending on the available compute resources, budget, and business requirements, organizations can choose between Full Fine-Tuning and Parameter-Efficient Fine-Tuning (PEFT) techniques. Let's explore the concept of fine tuning in the below section.

Fine-Tuning:

Fine-tuning is the process of customizing a pre-trained model for a specific task. It builds on the knowledge gained from training on a large dataset and further trains the model using a smaller, task-specific dataset, resulting in improved accuracy while significantly reducing training time and computational effort.

Key Features of Fine-Tuning:

Fine-tuning enables organizations to adapt pre-trained AI models to specific tasks with minimal training effort. Its key features make it an efficient, cost-effective, and practical approach for developing high-performing, domain-specific AI applications.




Figure. 9.1: Key Features of Fine-Tuning

The figure highlights the major characteristics that make fine-tuning an efficient and practical approach for adapting pre-trained AI models to specific tasks. Each feature contributes to improved performance, reduced cost, and faster deployment of AI solutions.

Key features are:

* Uses Pre-trained Models: Builds on models already trained on large datasets, eliminating the need to train from scratch.

* Task-Specific Adaptation: Customizes the model for a particular domain, application, or business use case.

* Reduced Training Time: Requires significantly less time and computational resources than full model training.

* Improved Performance: Enhances accuracy and relevance for specialized tasks by learning from domain-specific data.

* Efficient Data Usage: Achieves good results using relatively small, labeled datasets.

* Knowledge Retention: Preserves the model's general language understanding while learning new task-specific knowledge.

* Cost-Effective: Lowers infrastructure and training costs by leveraging existing model capabilities.

* Cloud Integration: Can be performed efficiently using managed cloud AI platforms with built-in training, monitoring, and deployment services.

How fine-tuning works?

Fine-tuning adapts a pre-trained model to a specific task by continuing its training on a smaller, task-specific dataset. Instead of learning from scratch, the model builds on its existing knowledge, making the process faster, more efficient, and less resource-intensive.


Figure. 9.2: Workflow of Fine-Tuning

The figure illustrates how transfer learning enables a pre-trained model to be adapted for a specific task using a smaller dataset, reducing training time and computational cost.

* Train on a Large Dataset: A model is first trained on a large dataset to learn general features and patterns.

* Transfer Learned Weights: The learned weights are transferred to a new model through transfer learning.

* Use a Small Dataset: A task-specific dataset is used to adapt the model to the target application.

* Retain Common Layers: The initial layers, which capture general knowledge, are kept unchanged or updated minimally.

* Fine-Tune Custom Layers: The final layers are retrained to learn domain-specific features.

* Generate Optimized Output: The fine-tuned model delivers accurate predictions for the target task with less training effort.


Types of Fine-Tuning:

Fine-tuning can be performed in different ways depending on the amount of available data, computational resources and the specific requirements of the task.

1. Full Fine-Tuning:

Full fine-tuning updates all the parameters (weights) of a pre-trained model using a task-specific dataset. Every layer of the neural network participates in training, enabling the model to learn domain-specific patterns comprehensively.


Figure. 9.3: Full Fine-Tuning

The figure illustrates the architecture of full fine-tuning, where the entire pre-trained neural network is retrained for a new task. During training, gradients flow through all layers, allowing every model parameter to be updated based on the task-specific dataset.

* Complete Pre-trained Network: The entire pre-trained model is used as the starting point for fine-tuning.

* Gradient Flow Across All Layers: Gradients propagate through every layer during backpropagation, enabling all weights to be updated.

* Updates All Parameters: Every parameter in the model is optimized to learn task-specific features and improve performance.

* End-to-End Learning: The model learns from input to output without freezing any layers, resulting in complete adaptation.

* Maximum Customization: Updating the full network allows the model to capture complex domain-specific patterns.

* High Resource Consumption: Since all parameters are retrained, full fine-tuning requires substantial computational power, memory, and longer training time.

Key Features of Full Fine-Tuning:

Full fine-tuning retrains all parameters of a pre-trained model using task-specific data, enabling complete adaptation to a new application. It provides the highest level of customization and accuracy but requires greater computational resources and training time.


Figure. 9.3: Key Features of Full Fine-Tuning

The figure highlights the core characteristics of full fine-tuning, where all parameters of a pre-trained model are updated to optimize performance for a specific task. This approach offers maximum customization but requires substantial computational resources.

* Updates All Model Parameters: Every layer and parameter of the pre-trained model is retrained, allowing complete model adaptation.

* Maximum Task Adaptation: The model fully learns domain-specific knowledge, making it suitable for highly specialized applications.

* High Accuracy and Performance: Updating all parameters enables the model to achieve superior accuracy on complex and task-specific problems.

* High Computational Requirements: Full fine-tuning demands powerful GPUs/TPUs, large memory, and significant storage for training and deployment.

* Longer Training Time: Since the entire model is retrained, the optimization process takes considerably more time than parameter-efficient methods.

* Ideal for Large Datasets: Full fine-tuning performs best when trained on large, high-quality labeled datasets, enabling the model to learn detailed domain-specific patterns.

Parameter-Efficient Fine-Tuning (PEFT) adapts a pre-trained model to a new task by updating only a small subset of model parameters while keeping most of the original model unchanged. This approach significantly reduces training time, memory usage, and computational cost without sacrificing much performance.

Common PEFT Techniques:

Parameter-Efficient Fine-Tuning (PEFT) includes several techniques that adapt large language models by training only a small subset of parameters. The most widely used PEFT methods are:

1. LoRA (Low-Rank Adaptation):

LoRA is one of the most widely used PEFT techniques. Instead of modifying all model weights, LoRA inserts small low-rank matrices into selected layers (typically attention layers) and trains only these additional matrices.

Key Features of LoRA:

Low-Rank Adaptation (LoRA) is a parameter-efficient fine-tuning technique that enables large language models to be adapted for specific tasks without modifying the original model weights.


Figure. 9.7: Key Features of LoRA

The figure illustrates key features of LoRA.

* Parameter Efficiency: LoRA updates only a small subset of parameters, significantly reducing memory consumption during both fine-tuning and inference.

* Computational Efficiency: By introducing lightweight low-rank matrices, LoRA reduces computational overhead, enabling faster training with lower GPU/TPU resource requirements.

* Preservation of Pre-Trained Knowledge: The original pre-trained model weights remain frozen, preserving existing knowledge while allowing task-specific adaptation and easy restoration of the base model.

* Scalability: LoRA can be integrated with a wide range of transformer-based models, such as GPT, BERT, and T5, making it suitable for diverse NLP tasks and deployment scenarios.

* Faster Fine-Tuning: Since only adapter parameters are optimized, LoRA considerably speeds up the fine-tuning process compared to full model fine-tuning.

Working of LoRA Fine-Tuning:

LoRA (Low-Rank Adaptation) fine-tuning updates only a small set of trainable adapter weights while keeping the original pre-trained model frozen. This enables efficient model adaptation with significantly lower computational cost, memory usage, and training time compared to full fine-tuning.




Figure. 9.6: Working of LoRA Fine-Tuning

The figure illustrates the Low-Rank Adaptation (LoRA) approach, where the pre-trained weights (??0) remain frozen and only two small trainable matrices, A and B, are learned. The output is obtained by combining the original model output with the low-rank adaptation, enabling efficient fine-tuning.

* Frozen Pre-trained Weights (??0): The original linear layer remains unchanged, preserving the knowledge learned during pre-training.

* Low-Rank Matrices (A and B): Two small trainable matrices are introduced to learn task-specific adaptations with far fewer parameters.

* Input Feature Processing: The input passes through both the frozen linear layer and the LoRA matrices simultaneously.

* Output Combination: The outputs from the frozen layer and the LoRA branch are added together to produce the final output feature.

* Selective Parameter Updates: During backpropagation, only the A and B matrices are updated, while the pre-trained weights remain fixed.

* Efficient Fine-Tuning: By training only the low-rank matrices, LoRA significantly reduces memory usage, computational cost, and storage requirements while achieving performance close to full fine-tuning.

2. QLoRA (Quantized Low-Rank Adaptation)

QLoRA extends LoRA by combining 4-bit model quantization with Low-Rank Adaptation. The base model is loaded in a compressed (quantized) format, while LoRA adapters are trained on top of it.


Figure. 9.7: Difference between LoRA and QLoRA

The following illustration provides a side-by-side comparison of LoRA and QLoRA, showcasing their architecture, precision, and resource requirements.

* LoRA (Low-Rank Adaptation): Trains only low-rank adapter layers while keeping the base model frozen, using 16-bit/32-bit precision.

* QLoRA (Quantized Low-Rank Adaptation): Combines low-rank adapters with 4-bit quantization to reduce memory usage.

* Memory Requirements: LoRA requires moderate GPU VRAM, whereas QLoRA operates with significantly lower VRAM.

* Fine-Tuning Approach: LoRA updates only adapter layers, while QLoRA fine-tunes adapters on a 4-bit quantized base model.

* Use Cases: LoRA is suitable for systems with adequate GPU resources, while QLoRA is ideal for memory-constrained hardware.

Working of QLoRA Fine Tuning:

QLoRA fine-tuning enables efficient adaptation of large language models by combining 4-bit quantization with Low-Rank Adaptation (LoRA). This approach significantly reduces GPU memory consumption while maintaining high model performance, making it ideal for cost-effective cloud-based fine-tuning.




Figure. 9.8: Working of QLoRA

The figure illustrates the step-by-step workflow of QLoRA (Quantized Low-Rank Adaptation) for efficiently fine-tuning large language models while minimizing memory and computational requirements.

Key Steps are:

* Quantize the Base Model: The pre-trained model is first converted into 4-bit precision, significantly reducing GPU memory requirements while keeping the original weights unchanged.

* Add Low-Rank Adapters: Lightweight LoRA adapter layers are inserted into selected layers of the quantized model. These adapters contain the trainable parameters.

* Fine-Tune Only Adapters: During training, only the adapter weights are updated using the task-specific dataset, while the quantized base model remains frozen. This minimizes computational cost and training time.

* Merge or Keep Adapters Separate: After fine-tuning, the adapters can either be merged with the base model for deployment or stored separately, enabling multiple task-specific adapters to share the same base model.

Advantages of QLoRA:

QLoRA offers an efficient and cost-effective approach to fine-tuning large language models by combining 4-bit quantization with Low-Rank Adaptation (LoRA). It significantly reduces memory and computational requirements while achieving performance comparable to full fine-tuning, making it ideal for cloud-based AI applications.

9.2 Distributed training and hyperparameter optimization

As the size of Large Language Models (LLMs) continues to grow, training them on a single GPU becomes time-consuming and computationally expensive. Distributed training enables model training across multiple GPUs or computing nodes, significantly reducing training time and allowing organizations to fine-tune large models efficiently. Hyperparameter optimization (HPO) complements distributed training by automatically identifying the best training parameters, resulting in improved model accuracy and performance.

Cloud platforms such as Amazon SageMaker, Microsoft Azure Machine Learning, and Google Vertex AI provide managed services for distributed training and automated hyperparameter tuning. These services simplify large-scale model training by offering scalable GPU clusters, experiment tracking, and automated optimization, enabling organizations to build high-quality AI models with reduced development effort. Let's explore these in the following section in more details.

Distributed Training:

Distributed training is the process of training a machine learning model using multiple GPUs or multiple computing nodes simultaneously. The training workload is divided across available computing resources, enabling faster processing of large datasets and models.

Need for Distributed Training:

Distributed training is essential for modern AI development because it overcomes the computational and memory limitations of a single machine. By leveraging multiple GPUs or compute nodes, it enables faster, scalable, and efficient training of large models on massive datasets. Key reasons are summarized in below table.

How Distributed Training Works?

Distributed training speeds up deep learning by dividing the training process across multiple GPUs or computing nodes. Each device performs a portion of the computation simultaneously, and the results are synchronized to ensure all devices learn the same model.




Figure. 9.11: Working of Distributed Learning

The figure illustrates the complete workflow of distributed training in a multi-GPU, multi-node environment. It demonstrates how training data is efficiently distributed across multiple processing units, enabling parallel computation and faster model training.

Key steps are:

* Data Source: The training dataset is collected from local, cloud, or distributed storage.

* Distributed Sampler: The dataset is partitioned into non-overlapping subsets, with each process receiving a unique portion of the data.

* Multi-Process Data Loading: Multiple worker processes load and preprocess the assigned data in parallel to improve throughput.

* Batch Tensor Creation: The processed data is organized into mini-batch tensors and distributed to the GPUs.

* Checkpoint-Restart Process: Model states, optimizer parameters, and training progress are periodically saved, enabling recovery in case of failures.

* Training Loop: Each GPU performs the forward pass, loss computation, backpropagation, and local gradient calculation on its assigned mini-batch.

* Distributed Data Parallel (DDP): Gradients from all GPUs are synchronized using collective communication (e.g., All-Reduce), ensuring identical model parameters across all devices.

* HPC System: Multiple GPUs across one or more compute nodes collaboratively execute the training workload using high-speed interconnects and communication libraries such as NCCL.

* Trained Model: After multiple synchronized training iterations, the optimized model is produced and is ready for evaluation or deployment.

Types of Distributed Training:

Distributed training can be categorized based on how the model, data, and computations are distributed across multiple GPUs or compute nodes. Each approach is designed to address different challenges related to memory, computational efficiency, and scalability.




Figure. 9.12: Types of Distributed Learning

The figure illustrates the two primary approaches to distributed training: Data Parallelism and Model Parallelism. They differ in how the training data and model are distributed across multiple workers (GPUs or compute nodes).

* Data Parallelism

o The training data is partitioned into multiple subsets.

o Each worker maintains a complete copy of the model.

o Every worker processes a different mini-batch independently.

o Gradients are synchronized after each iteration to update the model consistently.

Best suited for: Large datasets with models that fit into a single GPU.

* Model Parallelism

o The entire dataset is shared among all workers.

o The model is partitioned across multiple workers.

o Each worker computes only its assigned portion of the model.

o Intermediate outputs are exchanged between workers during forward and backward passes.

Best suited for: Very large models that cannot fit into the memory of a single GPU.

Organizations developing deep learning models for applications such as natural language processing, computer vision, recommendation systems, and generative AI often work with massive datasets and models containing millions or billions of parameters. Training these models on a single GPU is time-consuming and limited by memory capacity. Solution with AI:

Distributed training divides the training workload across multiple GPUs or computing nodes, allowing parallel execution of data processing and model computations. Depending on the application, techniques such as Data Parallelism, Model Parallelism, Pipeline Parallelism, or Hybrid Parallelism are used to improve scalability, optimize resource utilization, and accelerate model convergence.

Figure. 9.13 illustrates the workflow of distributed training through the following stages:

1. Data Distribution

1. Knowledge Distillation:

Knowledge distillation is a model compression technique in which a smaller, lightweight model is trained to replicate the behavior of a larger, more complex model. By transferring knowledge from the larger teacher model to the smaller student model, it produces efficient models that retain most of the original performance while requiring significantly fewer computational resources.

Working of Knowledge Distillation:

Knowledge distillation works by first training a large teacher model and then using its output predictions to guide the training of a smaller student model. The student learns to imitate the teacher's behavior, enabling it to achieve comparable accuracy with significantly fewer parameters and lower computational cost.

Key steps are:

2. Step 2: Knowledge Distillation: The teacher generates soft predictions (knowledge), which are transferred to the student model.

3. Step 3: Student Model Training: The student model learns from both the training data and the teacher's knowledge.

4. Step 4: Efficient Deployment: The trained student model provides similar performance with fewer parameters, lower memory usage, and faster inference.

2. Quantization:

Quantization is a model compression technique that reduces the numerical precision of a machine learning model's weights and activations while preserving most of its predictive accuracy. By representing values using fewer bits (such as 8-bit or 4-bit integers instead of

32-bit floating-point numbers), quantization significantly reduces model size, memory usage, and inference latency.

Objectives of Quantization:

Quantization aims to improve the efficiency of AI models by reducing their computational and memory requirements. It enables faster inference, lower power consumption, and easier deployment on resource-constrained devices while maintaining acceptable model accuracy.

* Reduce Memory Footprint: Quantization decreases model size by representing weights and activations with lower-precision data types, reducing storage and memory requirements.

* Speed Up Inference: Lower-precision computations execute faster, enabling quicker predictions and lower latency on CPUs, GPUs, and specialized AI hardware.

* Lower Computational Complexity and Energy Consumption: Fewer bits are processed during computations, reducing computational overhead, power consumption, and operational costs.

* Enable Edge Deployment: Compact quantized models can be deployed efficiently on smartphones, IoT devices, embedded systems, and other resource-constrained platforms.

* Maintain Accuracy: Well-designed quantization techniques preserve model accuracy with minimal performance degradation while significantly improving efficiency.

How It Works?

In deep learning models, parameters (weights and activations) are typically stored using 32-bit floating-point (FP32) numbers. While highly accurate, FP32 values consume significant memory and computational resources.

Quantization converts these values into lower-precision formats such as 8-bit integers (INT8), reducing storage requirements and accelerating computations.

This allows AI models to perform inference more efficiently with minimal impact on accuracy. By replacing 32-bit values with 8-bit values, the model requires less storage, transfers less data between memory and processors, and executes calculations faster.

Importance of Quantization:

Quantization plays a crucial role in making the fine-tuning of large AI models practical and cost-effective. By reducing the precision of model weights (e.g., from FP32 to INT8 or INT4), it significantly lowers memory requirements, enabling organizations to fine-tune models on affordable GPUs without compromising much on performance. 9.4 Domain adaptation and continual learning

Modern AI models often encounter new data distributions, evolving user requirements, and changing business environments after deployment. Domain adaptation enables models to transfer knowledge from one domain to another with minimal retraining, while continual learning allows models to learn from new data over time without forgetting previously acquired knowledge. Together, these techniques help AI systems remain accurate, relevant, and efficient in dynamic cloud and enterprise environments.

What is Domain Adaptation?

Domain adaptation is a transfer learning technique in which a model trained on a source domain is adapted to perform effectively on a target domain that has different data characteristics. Instead of training a new model from scratch, the existing model is fine-tuned using a smaller dataset from the target domain.

Why Domain Adaptation is Needed?

Domain adaptation is essential because AI models often encounter data in deployment that differs from the data used during training. By transferring learned knowledge to new domains, domain adaptation improves model robustness, reduces labeling costs, accelerates deployment, and enables AI systems to perform reliably in diverse real-world environments. The following table summarizes the key reasons why domain adaptation is essential in modern machine learning applications.

Improved Generalization

Types of Domain Adaptation:

Domain adaptation can be categorized based on the availability of labeled data in the target domain and the learning strategy used. Each type addresses different real-world scenarios to improve model performance across varying data distributions.

1. Supervised Domain Adaptation

* Uses labeled data from both the source and target domains.

* The target domain contains sufficient labeled samples for model adaptation.

* Typically achieves high accuracy but requires expensive and time-consuming data labeling.

2. Unsupervised Domain Adaptation

* Uses labeled source data and unlabeled target data.

* The model learns domain-invariant features to reduce the distribution gap without target labels.

* This is the most widely used approach because labeled target data is often unavailable.

3. Semi-Supervised Domain Adaptation

* Uses labeled source data along with a small amount of labeled and a larger amount of unlabeled target data.

* Combines supervised and unsupervised learning to improve adaptation performance.

* Provides a balance between labeling cost and model accuracy.

4. Multi-Source Domain Adaptation

* Uses labeled data from multiple source domains to adapt a model to a single target domain.

* Leverages diverse knowledge from several source datasets to improve robustness and generalization.

* Particularly useful when no single source domain closely matches the target domain.
