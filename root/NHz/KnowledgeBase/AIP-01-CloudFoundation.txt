Cloud Fundamentals

Overview

Cloud Fundamentals introduces the core concepts, technologies, and services that enable organizations to deliver computing resources over the internet. It provides an understanding of cloud computing models, service offerings, security practices, resource management, and cost optimization strategies used in modern cloud environments. This topic also explores cloud security, identity management, multi-cloud strategies, and infrastructure automation using Infrastructure as Code (IaC). By understanding these fundamentals, learners gain the knowledge required to design, deploy, manage, and optimize cloud-based solutions that support business agility, operational efficiency, and digital transformation.

This module covers:

* Cloud computing service models including Infrastructure as a Service (IaaS), Platform as a Service (PaaS), Software as a Service (SaaS), Serverless Computing, and Function as a Service (FaaS).

* Identity & Access Management (IAM), cloud security principles, and compliance fundamentals for securing cloud resources and data.

* Cloud billing models, cost optimization strategies, and cloud economics for efficient resource utilization and financial management.

* Multi-cloud concepts and comparative analysis of major cloud platforms including AWS, Azure, and Google Cloud.

* Infrastructure as Code (IaC) fundamentals using Terraform for automating and managing cloud infrastructure deployments.

* Real-world use cases demonstrating cloud adoption for scalable applications, data storage, disaster recovery, analytics, and digital transformation initiatives.

* Industry case studies showcasing successful cloud implementations, migration strategies, cost optimization practices, and business outcomes across various sectors.

1.1 Cloud Computing Models

Cloud computing is a technology that enables users to access computing resources such as servers, storage, databases, networking, and software over the internet instead of relying on local machines or physical infrastructure. It allows individuals and organizations to use these services on-demand, without needing to own or manage the underlying hardware. Cloud service providers host and maintain the infrastructure, ensuring availability, security, and performance.

Key Characteristics of Cloud Computing:



Figure. 1.1: Key Characteristics of Cloud Computing

The diagram illustrates the key characteristics of cloud computing, as defined by industry standards. These characteristics enable cloud platforms to deliver scalable, flexible, and cost-effective computing services over the internet. Key characteristics are:

* On-Demand Self-Service: Users can provision computing resources like servers and storage whenever required, without needing manual support from the provider.

* Broad Network Access: Cloud services are accessible over the internet and can be used on various devices such as laptops, smartphones, and tablets.

* Resource Pooling: The provider's resources are shared among multiple users, with dynamic allocation based on demand, ensuring efficient utilization.

* Rapid Elasticity: Resources can be easily scaled up during high demand and scaled down when not needed, providing flexibility and efficiency.

* Measured Service (Pay-as-you-go): Usage is monitored and billed based on consumption, making it cost-effective and eliminating unnecessary expenses.

Cloud Computing Models:

Cloud computing models define how cloud computing services are delivered to users over the internet. These models help organizations choose the right level of control, flexibility, and management based on their business and technical needs.


Figure. 1.3: Cloud Computing Models

The figure illustrates different cloud service models arranged according to the level of resource management required from users. Moving from IaaS to SaaS, the responsibility for

managing cloud resources gradually shifts from the user to the cloud provider. As a result, users gain greater simplicity and convenience but have less control over the underlying infrastructure. Let's explore these in below section.

* Infrastructure as a Service (IaaS):

IaaS provides fundamental computing resources such as virtual servers, storage, and networking over the cloud. It offers the highest level of flexibility and control, enabling organizations to configure and manage infrastructure according to their requirements.


Figure. 1.4: Overview of Infrastructure as a Service (IaaS)

The diagram illustrates the key components of Infrastructure as a Service (IaaS), where cloud providers deliver virtualized infrastructure resources over the internet. IaaS enables organizations to access computing resources on demand without investing in physical hardware, offering scalability, flexibility, and cost efficiency.

Key Components of IaaS:

* Data Center: Provides the physical infrastructure that hosts cloud resources, including servers, storage systems, and networking equipment.

* Servers: Deliver computing power for running applications, workloads, and operating systems in a virtualized environment.

* Network and Storage: Offer connectivity and data storage services, enabling secure communication and efficient data management.

* Virtualization: Abstracts physical hardware into virtual resources, allowing multiple virtual machines to run on shared infrastructure.

Examples: AWS EC2, Azure Virtual Machines, Google Compute Engine

* Platform as a Service (PaaS):

PaaS provides a complete platform for developing, testing, deploying, and managing applications. Developers can focus on writing code while the cloud provider manages infrastructure, operating systems, and development tools. PaaS doesn't completely replace a company's IT infrastructure. Rather, it uses a cloud service provider to provide users access to a runtime environment for app development via a web browser.




Figure. 1.5: Overview of Platform as a Service (PaaS)

The image illustrates the key components of Platform as a Service (PaaS) in cloud computing.

* Hosting: Provides cloud-based servers to run applications without managing hardware.

* Database: Offers managed data storage with automatic scaling and maintenance.

* Network	Access:	Enables	internet	connectivity	for	application	access	and communication.

* Operating System: Supplies and manages the underlying OS environment.

* Software: Delivers development tools and runtime environments for building apps.

* Security: Ensures protection of data, applications, and platform through built-in safeguards.

Key Insight: The PaaS abstracts infrastructure and platform management, allowing developers to focus only on building and deploying applications rather than maintaining underlying systems.

Examples: Google App Engine, Azure App Service, Heroku

* Software as a Service (SaaS):

In the Software as a Service (SaaS) model, applications are hosted on the provider's cloud infrastructure and delivered to users over the internet. Customers access the software through a web browser, usually on a subscription basis. SaaS eliminates the need for local installation, server management, and software maintenance, as updates, security patches, and infrastructure management are handled by the service provider.




Figure. 1.6: Overview of Software as a Service (Saas)

This diagram illustrates the Software as a Service (SaaS) model in cloud computing. It shows how software applications are delivered over the internet, where all infrastructure, platform, and application components are managed by the service provider, allowing users to access services directly through devices like PCs and mobile phones.

* Networks: Provides internet connectivity to access cloud-based applications.

* App Server: Hosts and runs the software applications on the cloud.

* Mobile: Enables access to SaaS applications through smartphones and tablets.

* Codes: Represents the application logic managed and delivered by the provider.

* Database: Stores and manages application data in the cloud.

* PCs: Allows users to access SaaS applications via desktop or laptop devices.

Examples: Google Workspace, Microsoft 365, Salesforce

* Serverless Computing:

Serverless computing enables developers to run applications without managing servers or infrastructure. The cloud provider automatically provisions resources, scales applications, and handles maintenance tasks.


Figure. 1.7: Serverless Computing

This diagram explains the concept of Serverless Computing in cloud computing. It shows how cloud providers automatically handle server provisioning, scaling, and maintenance, allowing developers to run applications without managing underlying infrastructure.

Key Characteristics of Serverless Computing are:

* Event-driven: Functions execute only when triggered by events.

* Scalable: Resources automatically scale up or down based on demand.

* Ephemeral: Execution instances are temporary and short-lived.

* Pay-as-you-go: Users are charged only for actual usage.

* No Server Management: No need to maintain or manage servers.

Examples: AWS Lambda, Azure Functions, Google Cloud Functions

* Function as a Service (FaaS):

FaaS is a serverless execution model where developers deploy individual functions that run in response to specific events. It is particularly suitable for microservices and event-driven applications.


Figure. 1.8: Faas Cloud Architecture

The image illustrates the Function as a Service (FaaS) architecture, a serverless computing model where applications are executed as independent functions in the cloud.

Flow of Architecture:

* Event Sources: Inputs such as users, web requests, or APIs trigger events.

* FaaS Cloud Platform: The cloud platform receives these events and manages execution automatically.

* Functions: Small, independent pieces of code are executed in response to events.

* Serverless Containers: Functions run inside temporary containers without manual server management.

* Cloud Storage: Data required for processing is stored and accessed from cloud storage services.

Relationship Between Serverless and FaaS:

Although often used interchangeably, Serverless Computing and FaaS are not identical:

* Serverless Computing is the broader cloud computing paradigm where infrastructure management is abstracted from users.

* FaaS is a subset of serverless computing that focuses specifically on executing individual functions in response to events.

1.3 Identity & Access Management (IAM), Security & Compliance basics
Identity & Access Management (IAM), Security, and Compliance are fundamental components of cloud computing that help protect cloud resources, applications, and data from unauthorized access and cyber threats. IAM ensures that only authorized users can access specific resources, while security mechanisms safeguard the confidentiality, integrity, and availability of information. Compliance focuses on meeting regulatory, legal, and industry standards to ensure secure and responsible management of data and cloud environments.

Together, IAM, security, and compliance enable organizations to establish a secure cloud infrastructure, manage user permissions effectively, reduce security risks, and maintain trust among customers, stakeholders, and regulatory authorities. Let's explore these in the below section.

Identity & Access Management (IAM):

Identity & Access Management (IAM) is a cloud security service that controls who can access cloud resources and what actions they can perform. It ensures that only approved users and services can perform specific actions within an environment.

Objectives of IAM:

* Verify user identities.

* Control access to resources.

* Enforce security policies.

* Protect sensitive data.

* Reduce unauthorized access risks.

Components of IAM:

Identity and Access Management (IAM) is a framework that ensures the right users have appropriate access to cloud resources while maintaining security and compliance.


Figure. 1.14: Key Components of Identity and Access management (IAM)

The diagram represents key components of IAM:

1. Authentication: The process of verifying a user's identity before granting access.

Examples:

* Username and password

* Multi-Factor Authentication (MFA)

* Biometric authentication

2. Authorization: Determines what resources and actions a user is permitted to access after authentication.

Examples:

* Read-only access

* Administrator privileges

* Resource-specific permissions

3. User Management: Handles the creation, modification, and deletion of user accounts and identities.

4. Role-Based Access Control (RBAC): Permissions are assigned based on user roles rather than individual users.

Examples:

* Administrator

* Manager

* Employee

* Guest User

5. Single Sign-On (SSO): Allows users to access multiple applications using a single set of login credentials.

Working of IAM:

Identity and Access Management (IAM) controls who can access cloud resources and what actions they can perform. It ensures secure authentication and authorization of users and applications.



Figure. 1.15: Working of Identity and Access management (IAM)

The diagram shows how AWS Identity and Access Management (IAM) controls access to AWS resources through identities and permissions. Key steps involved:

* User Login: A user attempts to access a cloud resource or application.

* Authentication: IAM verifies the user's identity using credentials such as passwords, security tokens, or Multi-Factor Authentication (MFA).

* Authorization: After successful authentication, IAM checks the user's assigned roles, groups, and policies.

* Access Evaluation: IAM determines whether the requested action is allowed or denied based on defined permissions.

* Resource Access: If authorized, the user is granted access to the requested cloud resource.

* Monitoring and Auditing: IAM logs user activities and access events for security monitoring, compliance, and auditing purposes.

Security in Cloud Computing:

Security in cloud computing refers to the policies, technologies, controls, and practices used to protect cloud-based systems, applications, networks, and data from unauthorized access, cyberattacks, data breaches, and other security threats. It ensures the confidentiality, integrity, and availability of information while enabling organizations to operate securely in cloud environments.

Objectives of Cloud Security:

* Protect sensitive data and applications.

* Prevent unauthorized access.

* Ensure business continuity.

* Detect and respond to cyber threats.

* Maintain compliance with regulations.

* Minimize financial and reputational risks.

Core Security Principles:

Core security principles provide the foundation for protecting information systems, data, and cloud resources from unauthorized access, misuse, and cyber threats.


Figure. 1.16: Core Security Principles

* Confidentiality: Confidentiality ensures that sensitive information is accessible only to authorized individuals or systems. It protects data from unauthorized access and disclosure through mechanisms such as encryption, authentication, and access controls.

Examples:

o Password-protected systems

o Data encryption

o Role-based access control (RBAC)

* Integrity: Integrity ensures that data remains accurate, consistent, and unaltered throughout its lifecycle. It protects information from unauthorized modification, corruption, or deletion.

Examples:

o Hashing and digital signatures

o Version control systems

o Database integrity constraints

* Availability: Availability ensures that data, applications, and systems are accessible whenever authorized users need them. It focuses on minimizing downtime and maintaining reliable access to resources.

Examples:

o Backup and disaster recovery

o Load balancing

o Redundant servers and storage

Compliance in Cloud Computing:

Compliance is the process of following established rules, standards, policies, and regulations designed to protect sensitive information and ensure responsible business operations. Organizations must demonstrate that their cloud environments meet specific security and privacy requirements through audits, monitoring, and documentation.

Objectives of Compliance:

* Protect sensitive and confidential data.

* Ensure regulatory and legal adherence.

* Reduce security and operational risks.

* Maintain customer trust and confidence.

* Support governance and accountability.

* Facilitate audits and reporting.

Key Components of Compliance:

Compliance ensures that organizations adhere to legal, regulatory, industry, and organizational requirements for protecting data and maintaining security standards.


Figure. 1.17: Key Components of Compliance

The diagram highlights the essential components that contribute to an effective compliance framework. Compliance ensures that organizations operate according to legal, regulatory, and organizational requirements while maintaining transparency and accountability.

* Policies: Policies are formal guidelines that define an organization's expectations, responsibilities, and security requirements. They provide a framework for decision-making and operational activities.

* Standards: Standards establish specific criteria, procedures, and technical requirements that support policy implementation. They ensure consistency and uniformity across the organization.

* Rules: Rules are detailed instructions that define acceptable and prohibited actions. They help enforce policies and maintain operational discipline.

1.4 Billing, Cost optimization, and Cloud economics

Billing provides visibility into cloud spending, cost optimization focuses on reducing unnecessary expenses while maintaining performance, and cloud economics helps organizations evaluate the financial benefits of cloud adoption and make informed business decisions.

Cloud Billing:

Cloud billing refers to the process of tracking, measuring, and charging for cloud resource consumption. Cloud service providers charge customers based on actual usage of computing resources such as virtual machines, storage, databases, networking, and managed services.

Unlike traditional IT infrastructure, where organizations make large upfront investments, cloud billing follows a consumption-based pricing model, allowing businesses to pay only for the resources they use.

Key Characteristics of Cloud Billing:

* Pay-as-You-Go Pricing: Customers are billed based on actual resource utilization e.g. compute hours consumed, storage capacity used etc.

* Usage-Based Metering: Cloud providers continuously monitor resource usage and calculate charges accordingly.

* Flexible Pricing Models: Organizations can choose pricing plans based on workload requirements and budget constraints.

* Detailed Cost Visibility: Cloud platforms provide dashboards and reports that help monitor spending across services, teams, and projects.

1.6 Infrastructure as Code (IaC) basics with Terraform

Infrastructure as Code (IaC) is the practice of managing and provisioning infrastructure through code instead of manual processes. It allows developers and cloud engineers to define servers, networks, storage, and other cloud resources using configuration files that can be version-controlled, reused, and automated.

How Infrastructure as Code (IaC) works?

Infrastructure as Code (IaC) is an approach that automates the provisioning, configuration, and management of infrastructure through machine-readable code. Commonly known as "Programmable Infrastructure," it helps organizations achieve scalability, repeatability, and faster deployment cycles.




Figure. 1.21: Working of of Infrastructure as Code (IaC)

The diagram illustrates the workflow of Infrastructure as Code (IaC), where infrastructure is defined, managed, and deployed using code instead of manual configuration.

Step-by-Step Process:

1. Step 1: Developer Writes Infrastructure Code

* The process begins with a developer creating infrastructure definitions in the form of:

o Scripts

o Templates

o Policies

* These files describe the desired state of the infrastructure.

2. Step 2: Store Code in Version Control

* The infrastructure code is stored in a version control system (such as Git).

* This enables collaboration, version tracking, auditing, and rollback of changes when needed.

3. Step 3: IaC Tools Process the Code

* The code is then consumed by IaC and configuration management tools such as:

o Terraform

o Ansible

o Chef

o Puppet

o AWS CloudFormation

4. Step 4: Push and Pull Operations

* The tools interact with infrastructure through push and pull mechanisms.

* They compare the desired infrastructure state defined in code with the actual environment and apply necessary changes.

5. Step 5: Infrastructure Provisioning

* Based on the code, resources are automatically created, updated, or removed.

* These resources may include servers, databases, networks, storage systems, and cloud services.

6. Step 6: Continuous Management

* Any future modifications are made in the code and redeployed through the same workflow.

* This ensures consistency, repeatability, and efficient infrastructure management.

Benefits of using IaC:

* Automation: Eliminates manual infrastructure provisioning.

* Consistency: Same configuration creates identical environments.

* Version Control: Infrastructure changes are tracked and auditable.

* Collaboration: Multiple teams can work on infrastructure safely.

* Scalability: Resources can be provisioned and modified quickly.

* Reusability: Modules stored in registries reduce duplication.

* Disaster Recovery: Infrastructure can be recreated from code.

Case Study 1:

This case study highlights how Netflix leveraged cloud infrastructure to support its rapidly growing global streaming service. By adopting AWS, Netflix achieved high scalability, reliability, and performance, enabling seamless content delivery to millions of users worldwide. It demonstrates the role of cloud computing in building resilient and scalable digital platforms.

Title: Netflix Leveraging AWS Cloud Infrastructure for Global Streaming Scalability
Background:

Netflix is one of the world's leading video streaming platforms, serving millions of subscribers across numerous countries. As its user base grew rapidly, the company needed an infrastructure capable of handling massive amounts of streaming traffic, ensuring high availability, and delivering content seamlessly across different regions. To achieve this, Netflix migrated its services to cloud infrastructure, utilizing the capabilities of Amazon Web Services (AWS) to build a highly scalable and resilient streaming platform.

* Organization: Netflix

* Target Industry: Entertainment and Media Streaming

Problem Statement:

Netflix faced several challenges while operating on traditional data center infrastructure:

* Rapid growth in global subscribers led to unpredictable traffic spikes.

* Maintaining high availability and uninterrupted streaming services was difficult.

* Scaling infrastructure to support millions of concurrent viewers required significant investment.

* Disaster recovery and fault tolerance across geographic regions were complex and costly.

* Delivering high-quality streaming content with minimal latency worldwide was becoming increasingly challenging.

Proposed Solution:

Netflix adopted a cloud-first strategy and migrated its infrastructure to AWS. The company utilized various AWS services to create a scalable and reliable streaming ecosystem:

* Amazon EC2 for elastic computing resources.

* Amazon S3 for storing vast amounts of video content and metadata.

* Auto Scaling to dynamically adjust resources based on user demand.

* Elastic Load Balancing (ELB) to distribute traffic efficiently.

* Multiple AWS regions and availability zones to ensure redundancy and fault tolerance.

* Cloud-based monitoring and automation tools to improve operational efficiency and service reliability.



Outcome:

The migration to AWS delivered significant business and technical benefits:

* Successfully supports millions of users streaming content simultaneously worldwide.

* Achieved near-continuous service availability through distributed cloud architecture.

* Improved scalability by automatically allocating resources during peak viewing periods.

* Reduced infrastructure management overhead and accelerated innovation.

* Enhanced disaster recovery capabilities and operational resilience.

* Enabled rapid global expansion without the need for building physical data centers.

Key Takeaways:

Cloud infrastructure provides virtually unlimited scalability for global digital services.

* Elastic	resource	allocation	helps	organizations	manage	fluctuating	workloads efficiently.

* Distributed cloud architectures improve availability, reliability, and fault tolerance.

* Cloud adoption reduces infrastructure maintenance efforts and enables faster innovation.

* Organizations can expand globally more quickly by leveraging cloud service providers instead of investing in physical infrastructure.
