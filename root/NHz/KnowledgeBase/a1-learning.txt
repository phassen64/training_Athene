$   fault vs error vs failure

    While often used interchangeably in casual 
        conversation, 
        fault and error represent distinct 
        stages in a cause-and-effect chain 
    within systems, software, and engineering:

    •   fault 
        definition:    
            The underlying cause, defect, 
                flaw, or mistake in the system or code.
        key difference:    
            Cause (Static / Latent)
        example:
            A programmer writes '>' instead of '>=' 
            in a conditional loop.
    
    •   error    
        definition:
            The incorrect internal state resulting 
                from a fault during execution.
        key difference:
            Manifestation (Dynamic)
        example:
            A variable holds a value of 10 
                when it should be 11.

    •   failure 
        definition:
            The observable incorrect behavior 
                visible to the end user or external system.
        key difference:
            Effect (External Result)
        example:
            The application crashes or produces an 
                incorrect final total on screen.

=== m:  [1.6]   Infrastructure as Code (IaC) Basics with Terraform

+   What is IaC ?

    01  IAC manages infrastructure thorough code, 
        not manual    processes            
   
    02  developers define servers. networks, storage 
        and cloud seources 

    03  using configuration files are version-controlled,
        resusable and automated 
        
        
+   How IaC works ?

    1.  IaC automates infrastructure through machine-readable code    
    2.  it enbales scalability, repeatable and faster deployment with 
        less manual effort
        
+   IaC workflow 
    step1:  developer define infrastructure using 
                scripts, templates or policies 
    step2:  the files are stored in a version control system 
                for collaboration, version tracking, auditing and rollback
    step3:  tools like 
            •   Terraform 
            •   Ansible 
            •   Chef
            •   Puppet
            •   AWS CloudFormation
    step4-6:
            •   servers 
            •   databases 
            •   storage 
            •   networks
            •   cloud services 
            actions:
                create & update & remove

+   example 
    Terraform
        provider "aws" {        *   welcher CSP 
        region = "us-west-2"    *   welcher region 
    }
    resource "aws_instance" "example" {
        ami           = "ami-0c55b159cbfafe1f0"     *   instance id 
        instance_type = "t2.micro"      *   welche provisioning model
        tags = {
            Name = "IaC-Managed-Instance"
        }
    }
               

+   Benefits of IaC 
    ... delivers consistent environments
    ... encourages reusable modules 
    ... simplifies disaster recovery by recreating infrastructure from code
    
+   Approaches of IaC 
    1.  declarative 
        •   Terraform 
        •   AWS CloudFoundation 
        •   Kubernet YAML 
        focus : "what the infrastructure should look like"
        
    2.  imperative
        •   Ansible 
        •   bash scrips 
        •   powershell scripts
        focus : "how to achieve the desired state"


$   Was ist Infrastructure as Code (IaC)?

    •   Deklarativer Ansatz: 
        Sie beschreiben im Code den gewünschten Endzustand 
            Ihrer Infrastruktur 
            (z. B. Server, Netzwerke, Datenbanken),

    •   Wiederholbarkeit: 
        Sie können dieselbe Konfiguration beliebig 
            oft in Test-, Staging- und Produktionsumgebungen ausrollen.

    •   Versionskontrolle: 
        Infrastruktur-Code wird wie Anwendungscode in 
            Git gespeichert, nachvollziehbar geändert und per Rev

        A * A **-1 = A**-1 * A = I multiplizierst, erhältst du 1.

        Multiplizierst du eine quadratische Matrix $A$ mit ihrer inversen Matrix $A^{-1}$, 
    erhältst du die Einheitsmatrix $I$ (die Matrix, 
    die auf der Hauptdiagonale Einsen und sonst nur Nullen hat).
    $$A \cdot A^{-1} = A^{-1} \cdot A = I$$

        A scatter plot displays individual data points to reveal

            Correlation analysis, trend identification, and 
                outlier detection.
        Example: 
            Examining the relationship between advertising expenditure 
            and sales revenue.

    •   Box Plot: 
        Box Plot: 
            A box plot summarizes the distribution of data using quartiles 
            and highlights outliers.
        Use: 
            Detecting outliers and understanding data spread.
        Example: 
            Comparing salary distributions across different departments.

    •   Heat Map: 
        A heat map uses colors to represent data values or 
            correlation strengths between variables.
        Use: Correlation analysis and pattern identification.
        Example: 
            Visualizing correlations among features in a 
            machine learning dataset.

=== m:  [3.2]   Big Data Technologies

    url:    https://de.wikipedia.org/wiki/Big_Data

    Big Data technologies are designed to 
        store, process, and analyze massive volumes of 
    structured, semi-structured, and unstructured data that 
        traditional systems cannot handle efficiently. 
   
    Among the most widely used Big Data frameworks are 
        Apache Spark and 
        Apache Hadoop, 
    which enable organizations to process large 
        datasets across distributed computing environments. 
    
    Let's explore them in below section....


+   Apache Spark Overview:
    url:    https://spark.apache.org/

    ~ is a fast, 
        open-source distributed computing engine designed 
        for large-scale data processing and analytics. 

    It enables parallel data processing across 
        clusters of computers and is widely used 
    for big data workloads, 
        real-time analytics, 
        and machine learning applications.

    Spark supports multiple widely used programming languages 
        (Python, Java, Scala, and R), 
        includes libraries for diverse tasks ranging 
            from SQL to streaming and machine learning.

+   Spark Components 

    •   Apache Spark Core 
            is the foundation of the framework. 
            It provides distributed processing, memory management, 
            task scheduling, and fault tolerance.

    •   Spark Streaming 
            enables real-time data processing from continuous 
                data streams.
            
    •   MLlib 
            provides machine learning algorithms for 
            predictive analytics and data mining.

    •   Spark SQL 
        supports SQL queries and processing of 
            structured data using DataFrames.

    •   GraphX is used for graph processing and network analysis.
    

+   Core Features of Apache Spark

    •   Stream Processing
        Spark supports real-time processing of streaming 
            data, enabling continuous analysis of incoming 
            data such as logs, sensor data, and live events.
    
    •   Speed
        Spark is designed for high-speed computation by processing 
        data in memory, making it significantly faster than 
        traditional disk-based systems.
    
    •   Lazy Evaluation
        Spark does not execute operations immediately. 
        Instead, it builds a logical execution plan and 
        runs computations only when required, improving optimization.
    
    •   In-Memory Processing
        Data is stored and processed in RAM instead of disk, 
        which reduces I/O operations and increases processing efficiency.
    
    •   Concise
        Spark provides simple and expressive APIs (Python, Scala, Java), 
        allowing developers to write less code for 
            complex data processing tasks.

+   Apache Spark Architecture

    The diagram illustrates the high-level architecture of 
        Apache Spark, showing how an application is 
        executed across a distributed cluster.

    *   Application: User program using Spark APIs.
    *   Driver (Spark Session): 
        Creates execution plan, divides job into tasks, 
            schedules execution, collects results.
    *   Cluster Manager
        Allocates resources (e.g., Apache Hadoop YARN, Kubernetes).
    *   Executors (Worker Nodes):
        Run tasks in parallel and store intermediate data.
    *   Tasks & Partitions: 
        Data is split into partitions; each partition 
            is processed by one task.

+   Apache Hadoop Overview:
    url:    https://hadoop.apache.org/

    ~ is an open-source framework that allows the 
        distributed storage and processing of 
        large datasets across clusters of computers. 

    It is designed to scale from a single server to 
        thousands of machines, 
        providing high availability and fault tolerance.

+   Apache Hadoop Architecture 

    •   MapReduce
        A distributed programming model used to process 
        large datasets in parallel across multiple nodes. 
        It divides tasks into Map and Reduce phases for efficient computation.

    •   HDFS (Hadoop Distributed File System)
        A distributed storage system that stores large files across multiple machines. 
        It provides high fault tolerance and reliable data access.

    •   YARN (Yet Another Resource Negotiator)
        YARN is the resource management framework in the 
            Hadoop ecosystem that enables multiple processing engines, 
            such as MapReduce and Spark, 
            to efficiently share cluster resources.

    •   Hadoop Common
        A collection of shared libraries and utilities required 
            by other Hadoop modules. 
        It provides essential services such as configuration, 
        file management, and networking support.

=== m:  [3.4]   Data Quality, Governance, Versioning, and Cataloging


    As organizations collect and process massive amounts of data, 
        ensuring that data remains accurate, reliable, secure, 
        and easily discoverable becomes essential. 
    
    Data quality, governance, versioning, 
        and cataloging are critical components of 
        modern data management frameworks. 
        
    Together, 
        they help organizations maintain trust in data, 
            support regulatory


--- s:  [3.4].Data Quality

+   Key Dimensions of Data Quality

    *   Accuracy: 
        Accuracy refers to how correctly data represents real-world 
            values or facts. Accurate data is free from errors and ensures reliable decision-making.

    *   Completeness: 
        Completeness indicates that all required data fields are present 
        and populated. 
        Missing information can lead to incomplete analysis and 
        inaccurate insights.
    
    *   Consistency: 
        Consistency ensures that data remains uniform across 
            different systems, databases, and applications. 
        Consistent data improves reliability and prevents conflicts.

    *   Validity: 
        Validity measures whether data conforms to predefined formats, 
            rules, and business constraints. 
        Valid data supports smooth processing and analysis.

    *   Timeliness: 
        Timeliness refers to the availability of current and 
            up-to-date data when needed. 
        Timely data enables faster responses and informed decisions.

    *   Uniqueness: Uniqueness ensures that each record is 
        distinct and free from unnecessary duplication. 
        Unique data reduces redundancy and improves data integrity.


--- s:  [3.4].Data Governance

    Data Governance is a structured approach to managing an 
        organization's data through defined 
            policies, processes, roles, and standards. 
   
    It ensures that data remains 
        accurate, consistent, secure, and accessible throughout its lifecycle. 
   
    By establishing clear ownership and accountability, 
        data governance helps organizations improve data quality, 
        maintain regulatory compliance, reduce risks, and support reliable decision-making.

--- s:  [3.4].Cataloging

    Data cataloging is the process of creating an 
        organized inventory of data assets within an organization. 
    A data catalog provides 
        metadata, descriptions, ownership information, 
        and usage details, making data easier to discover and understand.


--- s:  [3.4].Versioning


    Data versioning is the process of 
        tracking, managing, and storing changes 
        made to datasets over time. 
    
    Similar to source code version control in software development, 
        data versioning enables organizations to maintain 
        multiple versions of data, track modifications, 
        and reproduce results using specific dataset versions.

    As data continuously evolves through updates, 
        corrections, and new records, 
        versioning helps ensure consistency, traceability, 
        and reliability across analytics, reporting, and AI workflows.


+   Concept of Data Versioning

    The diagram represents data versioning in ML systems as a 
        combination of Data +  Model + Code, 
    where each component evolves independently and 
    jointly affects system behavior.

    *   Data Versioning 
        ~tracks changes in schema, sampling over time, 
        and data volume to ensure reproducibility of training datasets.

    *   Model Versioning captures changes in algorithms, 
        retraining cycles, and experiments to manage model evolution.

    *   Code Versioning manages business logic updates, 
        bug fixes, and configuration changes affecting pipeline behavior.

+   Key Features of Data Versioning

    *   Change Tracking: 
        Records all modifications made to datasets, 
        including additions, updates, and deletions.

    *   Historical Snapshots: 
        Maintains previous versions of datasets for reference and recovery.

    *   Reproducibility:	
        Allows	analyst and	data scientists	to reproduce 
            reports, experiments, 
            and model results using the exact dataset version.

    *   Rollback Capability: 
        Enables restoration of earlier versions if errors 
        or data corruption occur.

    *   Collaboration Support: 
        Allows multiple users and teams to work on datasets 
        while maintaining version history.

    *   Auditability: 
        Provides a complete record of dataset changes for compliance 
        and governance purposes.


+   Types of Versioning 

    •   Snapshot-Based Versioning
        Stores complete copies of datasets at different points in time.
        Simple implementation; Easy recovery and restoration.
        High storage requirements.

    •   Incremental Versioning
        Stores only the changes made between dataset versions.
        Efficient storage utilization; Faster updates.
        More complex version management.

    •   Hybrid Versioning
        Combines snapshots and incremental changes to 
            balance storage and performance.
        Improved scalability; 
            Efficient version tracking; Balanced storage usage.
        More complex implementation and maintenance.

    Kafka architecture is a distributed system design that 
        enables high-throughput, fault-tolerant, 
        and real-time streaming of data between producers and consumers. 
    It is built to handle large-scale data pipelines efficiently 
    using a publish subscribe model.

    The architecture of Apache Kafka is built around 
        four core APIs within a Kafka cluster 
    (a group of one or more brokers in a distributed messaging system).

    *   Producer API: 
        Publishes records to one or more Kafka topics.

    *   Consumer API: 
        Subscribes to topics and reads records from them.

    *   Streams API: 
        Processes and transforms input streams into output streams 
        between topics.

    *   Connector API: 
        Integrates Kafka with external systems 
        (e.g., databases) using reusable source and sink connectors.
