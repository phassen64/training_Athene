*   An upgrade is when you reinstall the program by using
    a newer version of that program, with a higher first figure
    of the version number. For example,
    your currently installed version of the program is 2.5.0.337,
    and you replace it with version 3.0.0.156.
    The upgrades are usually not free, but cost less than new licenses.
    Before you attempt to upgrade a program,
    visit the Pricing page of the product
    (e.g. CodeTwo Exchange Rules family, CodeTwo Exchange Rules Pro)
    to find out if you are eligible for a discount or check your purchase options.

*   A migration is when you stop using a program because you want
    to move to another product on preferential terms.
    For example, you no longer plan to use CodeTwo Exchange
    Rules 2007 in order to migrate to CodeTwo Exchange Rules Pro.
    The migration is not free, but you can get the new product at a discount.

F40:Zusammenfassung der Übungseinheit
>>> Frage
    In der Übungseinheit haben Sie den Nano-Server
    auf einem virtuellen Computer ausgeführt.
    Wenn Sie den Nano-Server nach der Erstellung
    Ihrer virtuellen Festplatte auf einem physischen Host ausführen wollen,
    welche Befehle verwenden Sie zur Konfiguration der Startumgebung?
<<< Antwort
    So ändern Sie die Starteinstellungen eines physischen Computers
    für die Nutzung der virtuellen Festplatte für Nano-Server:
    Kopieren Sie in einer Eingabeaufforderung
    mit erhöhten Rechten den vorhandenen Eintrag für das
    Startladeprogramm auf den Computer,
    auf dem Nano-Server ausgeführt werden soll,
    und verwenden Sie diesen, um mit dem
    Befehl bcdedit /copy {current} /d “Nano Server” einen neuen Eintrag zu erstellen.
    Geben Sie erneut bcdedit ein und kopieren Sie die GUID inklusive der Klammern ({ }), die im Feld ID des neu kopierten Eintrags für das Startladeprogramm angezeigt wird.
    Führen Sie folgende Befehle aus, wobei Sie {GUID} mit der kopierten GUID inkl. Klammern ersetzen:
    bcdedit /set {GUID} device vhd=C:\NanoServer\NanoServer.vhd
    bcdedit /set {GUID} osdevice vhd= C:\NanoServer\NanoServer.vhd
    bcdedit /set {GUID} path \windows\system32\boot\winload.exe
    Überprüfen Sie, ob die Einstellungen korrekt sind,
    indem Sie die Systemeigenschaften aufrufen.
    Wählen Sie Startup and Recovery settings (Start- und Wiederherstellungseinstellungen).
    Sie sollten sehen können, dass im Systemstart Nano-Server aufgelistet wird.
    Alternativ stellen Sie die Datei NanoServer.vhd im Dateisystem mit Laufwerk G: bereit und führen Sie bcdboot G:\Windows aus.

F04:Auswählen eines Partitionstabellenformats
+   MBR "MasterBootRecord"
    Standard-Partitionstabellenformat seit den frühen 1980er Jahren
    Unterstützt maximal vier primäre Partitionen pro Laufwerk
    Kann einen Datenträger mit bis zu 2 TB partitionieren
+   GPT "GlobalPositionTable"
    GPT ist der Nachfolger des MBR-Partitionstabellenformats
    Unterstützt maximal 128 Partitionen pro Laufwerk
    Kann einen Datenträger mit bis zu 18 Exabyte partitionieren
=>  Verwenden Sie MBR für Datenträger, die kleiner als 2 TB sind
=>  Verwenden Sie GPT für Datenträger, die größer als 2 TB sind

F05:Auswahl eines Datenträgertyps
+   Basisdatenträger sind:
    +   Für Basisspeicher initialisiert
    +   Der Standardspeicher für das Windows-Betriebssystem
+   Dynamische Datenträger können:
    +   Ohne Neustart des Windows-Betriebssystems verändert werden
    +   Verschiedene Optionen für die Konfiguration von Volumes bieten
Anforderungen an Datenträgervolumes:
    +   Ein "Systemvolume" für hardwarespezifische Dateien,
        die zum Starten des Servers benötigt werden
    +   Ein "Startvolume" für die Windows-Betriebssystemdateien


F06:Auswahl eines Dateisystems
+   FAT bietet:
    Grundlegendes Dateisystem
    Begrenzungen bei der Partitionsgröße
    =>  FAT32 zur Unterstützung größerer Datenträger
    =>  exFAT für Speichersticks
+   NTFS bietet:
    +   Metadaten
    +   Überwachung und Journaling
    +   Sicherheit (ACLs und Verschlüsselung)
+   ReFS bietet:
    +   Abwärtskompatibilität zu NTFS
    +   Verbesserte Datenüberprüfung und Fehlerkorrektur
    +   Unterstützung für größere Dateien, Verzeichnisse und Volumes

F07:ReFS bietet eine Reihe von Vorteilen gegenüber NTFS
    +   Metadatenintegrität mit Prüfsummen
    +   Erweiterter Schutz vor Datenbeschädigung
    +   Große Volume-, Datei- und Verzeichnisgrößen
    +   Speicherpools und Virtualisierung
    +   Fehlertoleranz durch Redundanz
    +   Datenträgerbereinigung zum Schutz vor latenten Datenträgerfehlern
    +   Resilienz gegenüber Beschädigungen
    +   Gemeinsame, computerübergreifende Speicherpools

F20:Vergrößern und Verkleinern von Volums
Mit Windows Server 2016 können Sie die Größe von Volumes ändern.
Wenn Sie die Größe eines Datenträgers ändern möchten, beachten Sie Folgendes:
+   NTFS-Volumes lassen sich erweitern oder verkleinern

F21:RAID
RAID:
+   Fasst mehrere Datenträger in einer logischen Einheit zusammen,
    um für eine bessere Fehlertoleranz und Performance zu sorgen
+   Bietet Fehlertoleranz durch:
        a) Datenträgerspiegelung
        b) Paritätsinformationen
+   Kann durch Verteilung von Datenträger-E/A-Operationen
    auf mehrere Datenträger die Performance verbessern
+   Lässt sich mit verschiedenen Stufen konfigurieren
+   Sollte nicht als Ersatz für Serversicherungen dienen

F22:RAID-0
RAID0:= Striped Set ohne Parität oder Spiegelung
        Bsp:Datenträger0: A1,A3,A5,A7
            Datenträger1: A2,A4,A6,A8

F23:RAID-1
RAID1:=Gespiegelte Datenträger
        Bsp:Datenträger0: A1,A2,A3,A4
            Datenträger1: A1,A2,A3,A4

F24:RAID-5
RAID5:=Striped Set auf Blockebene mit Parität verteilt über alle Datenträger
    Bsp:    Datenträger0:   A1,B1,C1,D1

            Datenträger2:   A3,B3,Cp,D2
            Datenträger3:   A4,Bp,C3,D3

F06:DAS : "Direct Attached Storage"

+   Direct Attached Storage (DAS) oder
    Server Attached Storage bezeichnet an einen
    einzelnen Rechner angeschlossene Festplatten,
    die sich in einem separaten Gehäuse befinden

+   Vorteile:
    +   einfache Konfiguration
    +   kostengünstig
+   Nachteile:
    +   Isoliert, da die Datenträger mit einem einzelnen Server verbunden sind
    +   weniger Flexibilität bei der Zuweisung

+   übliche Schnittstellen: SCSI und SAS


F07:NAS  "Network Attached Storage"

+   Network Attached Storage
    (NAS, englisch für netzgebundener Speicher)
    bezeichnet einfach zu verwaltende Dateiserver.
    Allgemein wird ein NAS eingesetzt,
    um ohne hohen Aufwand unabhängige Speicherkapazität
    in einem Rechnernetz bereitzustellen.

+   NAS ist Speicher,
    der mit einem dedizierten Speichergerät verbunden
    und über Netzwerkfreigaben aufrufbar ist
    Zugriff: auf CIF|NFS-Netzwerk

+   Vorteile:
    +   NAS ist relativ günstig und stellt zentralen
        Speicher zum erschwinglichen Preis bereit
    +   Einfache Konfiguration

+   Nachteile
    +   Längere Zugriffszeiten
    +   Keine Lösung für Großunternehmen


F08:SAN  "Storage-Area-Network"

+   SANs bieten höhere Verfügbarkeit bei maximaler Flexibilität

+   Ein weiteres Problem der NAS-Systeme ist,
    dass diese zusätzlich das vorhandene LAN mit den Zugriffen
    auf die Daten belasten.
    Weiterhin ist das Ethernet, über das die NAS-Systeme
    mit den Servern bzw. den Clients verbunden sind,
    mit seinen geringen Rahmengrößen und seinem
    dabei relativ großen Protokoll-Overhead nicht
    für den schnellen Zugriff auf Massenspeicher ausgelegt

+   Vorteile:
    Kürzere Zugriffszeiten
    Leicht erweiterbar
    Zentrale Speicherung
    Hohe Redundanz

+   Nachteile:
    Mehr Kosten
    Setzt spezielle Kenntnisse voraus

+   SANs lassen sich mit Fibre Channel oder iSCSI implementieren


F10:Blockspeicher im Vergleich zu Dateispeicher
    a)  Blockspeicher:
        +   Hohe Leistung
        +   Oftmals SAN-basiert
        +   Wird Servern als LUNs präsentiert 
        +   Ist nicht die kosteneffektivste Lösung
    b)  Dateispeicher:
        +   Wird via NAS, einen Speicherserver
            oder einen Dateiserver bereitgestellt
        +   Nutzt CIFS/SMB (freigegebene Ordner) oder NFS (Exporte)
        +   Verwendet im Speicher-Back-End Blockspeicher

F12:Fibre Channel-Komponenten <siehe Kathrein> umfassen:

    +   Einen Computer mit einer HBA-Karte
    +   Einen Fibre Channel-Switch
    =   Fibre Channel-Anordnungen umfassen:

F13:Fibre Channel
    Infrastrukturerwägungen:
    +   Vorhandene Switch- und Kabelinfrastruktur
    +   Vorhandene Server und HBAs
    +   Vorhandene Speicherinfrastruktur
    Kosten:
    +   Fibre Channel ist meist teurer als andere Lösungen
    +   Umfangreiche Anfangsinvestitionen erforderlich
    +   Anfängliche und kontinuierliche Schulungen können die
    +   Ausgaben deutlich erhöhen

F14:iSCSI
    +   iSCSI-Ziele:
        Server, die auf dem Speichergerät ausgeführt werden

F24:MPIO  "Multi Path I/O"

+   Multipath I/O (MPIO) is a Microsoft
    framework designed to mitigate the effects of a host bus adapter (HBA)
    failure by providing an alternate data path
    between storage devices and a Windows operating system.
    MPIO enables up to 32 alternate paths to add redundancy
    and load balancing for Windows storage environments

+   MPIO requires at least two HBAs connected to
    the storage device. (A dual-port HBA may provide two data paths,
    but it still represents a single point of failure.)
    In a storage area network (SAN) you also need to ensure
    that any switches or routers laying in the data path have
    enough path management intelligence to handle disruptions caused
    by an HBA failure.

F13:Verwendungsszenarien für Speicherplätze

    sobald dieser in einen Speicherpool eingeführt wird.

    vorhanden sein.

+   Alle Laufwerke in einem Pool müssen dieselbe Sektorgröße verwenden.
+   Fibre Channel und iSCSI werden nicht unterstützt.

F31:Was ist Datendeduplizierung?

=   Datendeduplizierung:
+   Erkennt und entfernt Datenduplikate,
    ohne die Integrität oder Genauigkeit der Daten zu beeinträchtigen.
+   Ziel ist,
    mehr Daten auf geringerem Speicherplatz zu speichern.
=   Beim Aktivieren der Datendeduplizierung auf einem Volume
    wird eine Hintergrundaufgabe mit niedriger Priorität ausgeführt.
    Diese:
    +   Unterteilt Daten in kleine Blöcke unterschiedlicher Größe
    +   Erkennt doppelte Blöcke
    +   Ersetzt redundante Kopien durch eine Referenz
    +   Komprimiert Datenblöcke

F32:Was ist Datendeduplizierung? : Bild
=   Deduplikation (aus englisch deduplication),
    auch Datendeduplikation oder Deduplizierung,
    ist in der Informationstechnik ein Prozess,
    der redundante Daten identifiziert (Duplikaterkennung) und eliminiert,
    bevor diese auf einen nichtflüchtigen Datenträger geschrieben werden.
    Der Prozess komprimiert wie andere Verfahren auch die Datenmenge,
    die von einem Sender an einen Empfänger geschickt wird.
    Es ist nahezu unmöglich, die Effizienz bei der Verwendung von
    Deduplikations-Algorithmen vorherzusagen,
    da sie immer von der Datenstruktur und der Änderungsrate abhängig ist.
    Deduplikation kann eine sehr effiziente Methode sein,
    Datenmengen zu reduzieren,
    bei denen eine Mustererkennung möglich ist (unverschlüsselte Daten).

F16:Überlegungen hinsichtlich virtueller Festplattenformate und -typen
+   Erstellen Sie .VHDX virtuelle Festplatten,
    außer wenn Sie eine Abwärtskompatibilität mit Windows Server 2008
    oder Windows Server 2008 R2 benötigen.
+   Eine dynamisch erweiterbare virtuelle Festplatte im VHDX-Format
    eignet sich für Produktionsarbeitsauslastungen.
+   Der von dynamisch erweiterbaren virtuellen Festplatten
    angezeigte freie Speicherplatz ist nicht mit physischem freiem
    Speicherplatz gleichzusetzen.
+   Mehrere Ebenen mit differenzierenden Datenträgern
    mindern die Leistung.
+   Wird der übergeordnete Datenträger geändert, ist der
    differenzierende Datenträger nicht mehr gültig.
+   Sie können einen differenzierenden Datenträger mit
    einem übergeordneten Datenträger neu verknüpfen.


F17:Fibre-Channel-Unterstützung in Hyper-V
Der virtuelle Fibre Channel-Adapter:
+   Ermöglicht die direkte Verbindung eines virtuellen Computers
    mit einem Fibre-Channel-SAN.
+   Erfordert, dass der Hyper-V-Host einen
    Fibre-Channel-HBA aufweist.
+   Erfordert, dass der Fibre-Channel-HBA-Treiber
    virtuellen Fibre Channel unterstützt.
=   Erinnern Sie die Kursteilnehmer daran,
    dass der Hyper-V-Host bereits über einen
    Fibre-Channel-Hostbusadapter (HBA) verfügen muss und
    der Treiber virtuellen Fibre Channel unterstützen muss.
=   Fragen Sie die Kursteilnehmer,
    ob Sie Fibre Channel oder Internet SCSI (iSCSI)
    zur Verbindung mit ihrem Storage Area Network (SAN) verwenden

F29:Was sind Konfigurationsversionen des virtuellen Computers?
Konfigurationsversionen ermöglichen eine Kompatibilität
für virtuelle Computer zwischen:
+   Windows Server 2012 R2 (Version 5.0)
+   Windows Server 2016 (Version 5.0 oder 8.0)
+   Virtuelle Computer müssen manuell von Version 5.0 auf

    psh>Update-VMVersion “VMName”

F30:Generationsversionen von virtuellen Computern
Virtuelle Computer der 2. Generation bieten die folgende Funktionalität:
+   Sicherer Start
+   Startvorgang von einer virtuellen Festplatte,
    die mit einem virtuellen SCSI-Controller verbunden ist
+   Startvorgang von einer virtuellen DVD, die mit einem
    virtuellen SCSI-Controller verbunden ist
+   PXE-Start durch Nutzung eines standardmäßigen Hyper-V-Netzwerkadapters
+   UEFI-Firmwareunterstützung
=   Betonen Sie bei der Besprechung der Vorteile von
virtuellen Computern der 2. Generation,
dass viele Funktionen von virtuellen Computern der 1. Generation noch vorhanden sind,
um die bestehende Funktionalität der physischen Hardware zu replizieren.
Ein virtueller Computer der 2. Generation ist jedoch nur auf eine Ausführung
in einer virtuellen Umgebung ausgelegt und nicht auf die Replizierung
eines bestehenden physischen Computers.

+   "Produktionsprüfpunkte" werden über VSS erstellt
    und müssen aus einem Offlinezustand gestartet werden.

        wird aus einem bestimmten Grund inaktiv
    +   Eine der Ressourcen in der Instanz fällt aus
    +   Ein Administrator führt einen Failover durch
+   Der Clusterdienst kann das Failback durchführen,
    nachdem der Offlineknoten wieder online geschaltet wurde
+   Ein Failover kann geplant oder ungeplant sein

    +   Ausfall eines Knotens oder Zeugen und keine schnelle Wiederherstellung möglich
    +   Wiederherstellung eines Clusters in einem Notfallwiederherstellungsszenario mit mehreren Standorten

F55:Starten eines Clusters ohne Quorum
+   Clusterknoten müssen für die Funktion des Clusters das Quorum
    beibehalten
+   Wenn das Quorum verloren geht, versuchen Sie,
    das Quorum wiederherzustellen
+   Kann das Quorum über einen längeren Zeitraum nicht wiederhergestellt
    werden, starten Sie den Cluster im Modus ForceQuorum
+   Nachdem Sie den Cluster im ForceQuorum-Modus gestartet haben,
    können sich andere Knoten wieder dem Cluster anschließen
+   Nach der Wiederherstellung des Quorums ändert sich der
    Clustermodus automatisch von ForceQuorum zu normal
+   Beim Verbinden von Knoten mit dem Cluster,
    der sich im ForceQuorum-Modus befindet,
    sollten Sie andere Knoten mit einer Einstellung starten,
    die das Quorum verhindert

+   Speicherinfrastrukturdienste an jedem Standort konfigurieren

F64:Synchrone und Asynchrone Replikation
+   Bei der synchronen Replikation empfängt der Host
    eine Antwort vom primären Speicher,
    dass der <Schreibvorgang abgeschlossen> ist,
    nachdem die Daten erfolgreich auf =beide Speicherstandorten=
    geschrieben wurden.
+   Bei der asynchronen Replikation empfängt der
    Host eine Antwort vom primären Speicher,
    dass der <Schreibvorgang abgeschlossen> ist,
    nachdem die Daten erfolgreich in den =primären Speicher=
    geschrieben wurden.
    => schneller, aber Daten können inkonsistent sein

<<< Antwort
    Der Failovercluster funktioniert nicht mehr,
    wenn die logischen Gerätenummern (LUNs) ausfallen,
    die für den Quorumdatenträger verwendet werden.
    Auch wenn alle anderen Ressourcen verfügbar sind,
    einschließlich des Datenträgers für die Anwendungen,
    stellen Knoten keinen Dienst bereit,
    wenn der Quorumdatenträger nicht verfügbar ist.
    Er wird zur einzelnen Fehlerquelle.

F04:L1.1:Was ist NLB?
+   Skalierbare Hochverfügbarkeitstechnologie
+   Ermöglicht Lastenausgleich von Datenverkehr basierend auf Knotenauslastung:
    *   Neuer Datenverkehr wird an den am geringsten ausgelasteten Knoten geleitet
    *   Sie können NLB so konfigurieren, dass bestimmte Knoten bevorzugt werden.
+   Eignet sich für statusfreie Anwendungen wie:
    *   Webebenen von Mehrere-Ebenen-Anwendungen
+   Erkennt Ausfälle
+   Eignet sich nicht für statusbehaftete Anwendungen wie:
    Herkömmliche Dateiserver
    Datenbankserver

F05:Wie NLB funktioniert...

F06:Wie NLB mit Serverausfällen und -wiederherstellung umgeht...
+   NLB-Clustertakte werden jede Sekunde zwischen den Knoten in einem Cluster übertragen
+   Konvergenz tritt auf, wenn:
    *   Ein Knoten fünf aufeinanderfolgende Takte auslässt,
        woraufhin er automatisch vom NLB-Cluster entfernt wird
    *   Ein Knoten, der Mitglied eines Clusters war,
        wieder funktionsfähig wird
    *   Ein Administrator Knoten manuell hinzufügt oder entfernt


F07:Features in NLB - Windows Srever 2016
+   Nutzen Sie 35 NLB Windows PowerShell Cmdlets zur Verwaltung
    aller Aspekte der NLB-Konfiguration:
    *   Verwenden Sie NlbCluster Substantiv zur Verwaltung des Clusters
    *   Verwenden Sie NlbClusterNode Substantiv zur Verwaltung einzelner Knoten
+   Andere NLB-Features:
    *   Erfordert keine Hardwareänderungen
    *   Erfordert keine Anwendungssoftware-Änderungen
    *   Hosts können mehreren Clustern angehören
    *   Host können ohne Auswirkungen auf den restlichen
        Cluster hinzugefügt/entfernt werden

    Anwendungs- und Konfigurationsdaten für NLB-Anwendungen

+   Verwenden Sie Firewallregeln, um Datenverkehr zu verwerfen,
    der nicht mit Clusteranwendungen oder Knotenverwaltung zusammenhängt
+   Konfigurieren Sie Anwendungen, um nur den Datenverkehr zu bearbeiten,
    der an das Cluster adressiert ist
+   Verwenden Sie SANs, um Zertifikate zu erstellen,

+   Implementieren Sie das Prinzip der geringsten Berechtigung,
    damit nur autorisierte Benutzer Berechtigungen für Knoten erhalten

F17:Übungseinheit A: Implementieren von WSUS und Bereitstellen von Updates...
>   Frage
    Sie haben eine Gruppe für die Abteilung „Forschung“ erstellt.
    Warum würden Sie eine separate Gruppe für einige Computer
    Ihres Unternehmens konfigurieren?
<   Antwort
    Für die Abteilung „Forschung“ gelten möglicherweise
    spezielle Erwägungen oder Sicherheitsmaßnahmen,
    für die ein anderer Vorgang zum Testen und Genehmigen von Updates
    als für das restliche Unternehmen erforderlich ist.
    Darüber hinaus sind Administratoren in anderen Abteilungen möglicherweise
    für die Verwaltung des Updategenehmigungsverfahrens verantwortlich.
>   Frage
    Was ist der Vorteil der Konfiguration eines WSUS-Downstreamserver?
<   Antwort
    Wenn der WSUS-Hauptserver und der Downstreamserver über eine
    langsame WAN-Verbindung verbunden sind,
    lädt der WSUS-Downstreamserver die Updates nur einmal für die von
    ihm versorgten Clientcomputer herab.
    Andernfalls würde jeder Clientcomputer das Update gesondert über die WAN-Verbindung
    vom WSUS-Hauptserver herunterladen.

F60:Lernzielkontrolle
>   Frage
    Ihr Vorgesetzter hat Sie gefragt,
    ob alle Updates für das Betriebssystem Windows automatisch
    nach der Veröffentlichung installiert werden sollen.
    Empfehlen Sie einen alternativen Prozess?
<   Antwort
    Sie sollten alle Updates testen,
    bevor sie in einer Produktionsumgebung angewendet werden.
    Sie sollten Updates also zuerst mithilfe von WSUS auf einer
    Reihe von Testcomputern bereitstellen.
>   Frage
    Ihr Unternehmen implementiert verschiedene Anwendungen,
    die nicht von Microsoft stammen.
    Ein Kollege hat vorgeschlagen, WSUS zur Bereitstellung von
    Anwendungs- und Betriebssystemupdates zu verwenden.
    Kann der Einsatz von WSUS potenziell zu Problemen führen?
<   Antwort
    Ja. WSUS ist ein hervorragendes Tool zur Bereitstellung von
    Updates für Microsoft Anwendungen wie Microsoft Office
    und das Windows-Betriebssystem.
    Mit WSUS können jedoch nicht für alle Microsoft-Anwendungen und
    auch nicht für Microsoft-fremde Anwendungen Updates bereitgestellt werden.
    System Center 2012 Configuration Manager ist die bessere Wahl,
    wenn Sie Updates für Microsoft-fremde Anwendungen bereitstellen müssen.
>   Frage
    Warum lässt sich WSUS einfach in einer
    AD DS-Domäne (mit Active Directory-Domänendiensten) verwalten?
<   Antwort
    WSUS nutzt die Organisationseinheiten(OU-)Struktur von
    AD DS für die Bereitstellung von Clienteinstellungen
    über die Gruppenrichtlinie.
    Sie können die Gruppenrichtlinieneinstellungen auch zur Konfiguration
    einer clientseitigen Zielgruppenadressierung zur Bestimmung der WSUS-Gruppenmitgliedschaft
    eines Clientcomputers nutzen.
